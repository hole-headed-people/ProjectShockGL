# Задачи на будущее

## Виджет Text

- [ ] Добавить `FontSize` у виджета. Один растровый атлас должен работать с несколькими размерами текста. Измерение, перенос строк и выравнивание должны учитывать выбранный размер.
- [ ] Добавить начертания `Regular`, `Bold`, `Italic` и `BoldItalic` для всего виджета через отдельные TTF-файлы одной семьи.
- [ ] Добавить `AutoSize` с `MinFontSize` и `MaxFontSize`. Виджет выбирает самый крупный размер, при котором текст помещается в заданный `Rect` с учётом `WordWrap`. Если текст не помещается даже при минимальном размере, используется минимальный размер и обычное поведение `ClipToRect`.

## Виджет Image

- [ ] Добавить отдельный режим `Filled`: `Horizontal`, `Vertical`, `Radial360` с `FillAmount` от 0 до 1, выбором начала заполнения и направлением `FillClockwise` для радиального режима. Изображение отсекается вместе с UV, без сжатия; поддержать отдельную текстуру, регион атласа и обрезку родителем. Добавить настройки в UI Editor и сохранение в UI JSON. `Simple`, `Sliced` и `Filled` остаются отдельными режимами: совмещение Filled с 9-slice не требуется.

## Освещение

- [ ] Рассмотреть динамические тени от направленных, точечных и прожекторных источников света.
- [ ] Вернуться к запеканию прямого освещения и теней для всей статичной геометрии: статичных BrushBox, Geometry и Details. Все три вида должны и перекрывать запекаемый свет, и получать его результат. Общий вход запекателя — меши, мировые трансформы и свойства поверхностей; не опираться на коллайдеры или наследование от Object. Первый тест на BrushBox — этап проверки, а не ограничение архитектуры.
- [ ] Разделить источники на Baked и Realtime; по умолчанию Realtime для совместимости. Lightmap содержит Ambient и вклад Baked-источников с тенями. Статичные поверхности с готовой lightmap дополнительно получают только Realtime-свет, без повторного Ambient и Baked-вклада. Динамические объекты пока получают Ambient + Realtime; Baked на них не влияет. Статичные поверхности без lightmap используют Ambient + Realtime. Mixed, световые пробы, GI и AO пока вне первой версии; общий Ambient сам по себе стенами не перекрывается.
- [ ] Подготовить отдельные UV освещения без наложений, сохранив основные UV: автоматически для граней BrushBox, импортом или автоматической развёрткой для Geometry. Для каждого DetailPlacement обеспечить освещение его места, например собственной областью общего lightmap-атласа с координатами области в данных экземпляра; сохранить instancing. Учесть прозрачность текстур, односторонность поверхностей и ограничения шейдерных деформаций при запекании.
- [ ] Этапы запекателя: сбор треугольников статичного уровня, пространственное ускорение проверок видимости (например BVH), расчёт на CPU прямого света с теми же правилами источников, что в Lit, затем чтение lightmap в рендере. Проверить совместимость со статическим батчингом и instancing Details. Начать с небольшой комнаты из BrushBox и одного Baked-источника; затем подключить Geometry и Details. Отражённый свет добавить отдельным последующим этапом при необходимости.
- [ ] Хранить lightmap-ресурсы в Content, а ссылки и настройки — в уровне. Для объектов использовать GUID, для размещений Details — их стабильные Id. В редакторе предусмотреть Bake / Clear, плотность lightmap, отметку устаревшего результата, прогресс и отмену. Подменять прежний результат только после успешного запекания. Отдельная операция Bake Lighting достаточна: BSP-компиляция и VVIS-подобная видимость для неё не обязательны. Задача отложена до появления необходимости в текущей игре.
