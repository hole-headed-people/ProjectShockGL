# ProjectShockGL

Небольшой движок на C# и OpenGL с редактором уровней. Создаётся для системной игры от первого лица, вдохновлённой System Shock: исследование комнат, головоломки и связи между объектами уровня. Это личный инструмент; API развивается вместе с игрой.

При разработке движка активное используется Codex

Редактор ссылается на движок и ProjectOxygenGL — библиотеку конкретной игровой архитектуры. Для пользовательских классов игры добавьте небольшой проект запуска редактора в решение игры со ссылками на игру и ProjectShockGLEditor. Само ядро ProjectShockGL от игровых проектов не зависит.

## Сборка и запуск

Требования:

- .NET SDK 8.0; выбор SDK описан в [global.json](global.json).
- OpenGL 3.3 и подходящий драйвер видеокарты.
- Windows — основная среда разработки; другие платформы не проверены.
- Доступ к NuGet при первом восстановлении пакетов.

Из корня репозитория:

```sh
dotnet build ProjectShockGL.sln

```

Перед первым запуском редактора укажите абсолютный путь к папке StarterContent или Content своей игры в EditorSettings.ini. Затем запустите редактор командой `dotnet run --project ProjectShockGLEditor/ProjectShockGLEditor.csproj`.

В Rider или Visual Studio можно выбрать соответствующий стартовый проект. Кнопки Play внутри редактора пока нет: редактор и игра запускаются отдельно. Предупреждение NU1701 относится к целевой платформе используемого пакета ini-parser.

## Подключение своей игры и Content

### Папка ресурсов редактора

Редактору необходимо указать папку Content той игры, уровни которой он будет редактировать. Настройки находятся в [ProjectShockGLEditor/EditorSettings.ini](ProjectShockGLEditor/EditorSettings.ini):

```ini
[Content]
Path=Content
CustomPath=D:\MyGame\Content
```

Правила выбора пути в [Content.cs](ProjectShockGL/Content.cs):

1. Непустой CustomPath имеет приоритет над Path.
2. Абсолютный CustomPath используется напрямую.
3. Относительный CustomPath вычисляется от папки запущенного приложения — AppDomain.CurrentDomain.BaseDirectory, а не от корня репозитория и не от расположения исходного Settings.ini.
4. При пустом CustomPath используется Path относительно папки приложения. По умолчанию это Content рядом с exe.

В общей опубликованной папке оба приложения используют Path=Content и пустой CustomPath. Для отдельного запуска редактора из IDE укажите путь к Content в его EditorSettings.ini или обеспечьте копирование ресурсов в папку вывода.

Settings.Initialize(isEditor: true) читает EditorSettings.ini, Settings.Initialize(isEditor: false) (или вызов без аргумента) — GameSettings.ini. Оба файла ищутся рядом с запущенным приложением. Настройте CopyToOutputDirectory и CopyToPublishDirectory, чтобы INI попадали в сборку. После изменения исходного INI пересоберите приложение; уже опубликованные файлы можно редактировать непосредственно. Выбранный корень Content выводится в консоль.

Одной смены папки недостаточно для загрузки пользовательских классов: сборка с ними также должна быть доступна редактору. В JSON сущности указывается полное имя типа и сборки, например `MyGame.Placeables.Switch, MyGame`.

### Минимальная основа собственной игры

1. Создайте исполняемый проект .NET 8 со ссылкой на ProjectShockGL.
2. Добавьте GameSettings.ini и Layers.ini с копированием в папку сборки.
3. Подготовьте Content и настройте его копирование либо укажите CustomPath.
4. Создайте наследника ProjectShockGL.Core.Game и укажите его в Game/Class.
5. Подключите сборку игровых сущностей к редактору и задайте редактору этот же Content.

Точка входа:

```csharp
using ProjectShockGL;
using ProjectShockGL.Core;

Settings.Initialize(isEditor: false);
Game.Initialize();
Application.Run();
```

Пример выбора класса:

```ini
[Game]
Class=MyGame.MyGame, MyGame
PostProcessingProfile=Default
```

Базовый Game.Load загружает профиль постобработки, даже если эффекты вам не нужны. В Content должны быть необходимые стандартные шейдеры и валидный профиль Default; для отключения эффектов можно задать Enabled=false. Не начинайте с полностью пустой папки: скопируйте содержимое StarterContent в Content своей игры. Для своего жизненного цикла загрузки можно переопределить Game, учитывая обязанности базового Load.

## Первый уровень

Следующие шаги предполагают, что вы создали игру на ProjectOxygenGL и скопировали StarterContent в её Content:

1. Укажите Content игры в настройках редактора.
2. Выберите File → New или File → Open.
3. Нажмите Create BrushBox в Palette. Новый объект появляется в начале координат.
4. Соберите пол и стены, изменяя Transform. Назначьте текстуры.
5. Создайте PlayerStart из категории Placeables и поставьте над полом.
6. Добавьте свет; откройте Edit → Environment для окружения уровня.
7. Сохраните карту как Content/Levels/MyLevel.map.
8. В GameSettings.ini игрового проекта задайте `[Game] StartupLevel=MyLevel` и запустите игру.

Стартовый уровень читает [ProjectOxygenGL.Core.Game](ProjectOxygenGL/Core/Game.cs), он же создаёт игрока и персонажа после загрузки. В собственной игре эти действия определяет ваш Game.

### Пример связи уровня

1. Назовите объект `room_light` и снимите IsActive в Inspector.
2. Создайте Placeables/Trigger, разместите его область и включите CanTriggeredByPlayer.
3. Добавьте Output: Event=`OnTriggerEnter`, Target=`room_light`, Input=`SetActive`, Parameter=`true`.
4. Сохраните карту и проверьте её в игре.

Trigger и понятие игрока здесь принадлежат ProjectOxygenGL. В собственной игре условие активации определяется вашим кодом.

## Работа в редакторе

### Панели

| Панель / инструмент | Назначение |
| --- | --- |
| Scene | Список объектов, включая выключенные и скрытые |
| Groups | Группы редакторской видимости |
| Palette | Создание BrushBox, Geometry и Entity |
| Inspector | Transform, IsActive, свойства объекта и Outputs |
| Camera в верхней панели | Скорость и чувствительность камеры |
| Edit → Environment | Ambient, туман и другие параметры окружения уровня |

В Palette папки внутри Entities и Geometry становятся категориями. Поиск работает по имени и пути без учёта регистра и раскрывает найденные категории. Refresh перечитывает список после добавления файлов.

В выборе Texture у BrushBox также есть папки и поиск. Имя нового объекта короткое: `Placeables/TimerEvent` → `TimerEvent_1`. Путь ресурса сохраняется отдельно. Перенос файла ресурса требует обновления ссылок на него в картах.

### Управление

| Действие | Управление |
| --- | --- |
| Выбор | ЛКМ в сцене или строка Scene |
| Осмотр / движение камеры | ПКМ + мышь / WASD, Q/E вниз/вверх |
| Сдвиг камеры | Средняя кнопка мыши + движение |
| Фокус | F |
| Move / Rotate / Scale | G / R / T |
| Resize одного BrushBox | B или кнопка Resize |
| Изменение трансформа | Перетаскивание оси или кольца gizmo |
| Привязка | Snap или временное удержание любого Shift |
| Отмена перетаскивания | Esc |
| Дублирование / удаление | Ctrl+D / Delete |
| Undo / Redo | Ctrl+Z / Ctrl+Y |
| New / Open | Ctrl+N / Ctrl+O |
| Save / Save As | Ctrl+S / Ctrl+Shift+S |

### Resize BrushBox

Выделите один BrushBox и включите Resize в верхней панели или нажмите B над сценой. В центрах шести граней появляются ручки. Перетаскивание ручки изменяет Size вдоль локальной оси и сдвигает центр на половину фактического смещения грани; противоположная грань остаётся на месте. Поворот, неравномерный и отрицательный масштаб учитываются, Transform.Scale сохраняется.

Snap и удержание Shift привязывают смещение грани к Move step в мировых единицах. Минимальный локальный размер — 0.01; грань не проходит через противоположную сторону. При нулевом масштабе оси её ручки недоступны. Ручку, направленную точно вдоль взгляда, удобнее тянуть после небольшого поворота камеры.

Отпускание мыши сохраняет Size и позицию одним действием Undo/Redo; Esc восстанавливает исходное состояние. Коллайдер следует за Size, плотность текстуры сохраняется. Для нескольких объектов, Geometry и Entity этот режим не применяется. Resize изменяет коробку целиком и не добавляет редактирование вершин или выдавливание граней.
### Groups

1. В отдельной панели Groups введите имя и нажмите Create group.
2. Выделите объект, раскройте группу и нажмите Add selected.
3. Remove исключает объект; Delete group удаляет группу, сохраняя объекты.
4. Переключатель у имени скрывает или показывает группу.

Один объект может входить в несколько групп; скрытие любой из них скрывает его. Скрытые объекты не рисуются, не выбираются мышью в сцене и не показывают gizmo; скрытый свет не освещает предпросмотр. Через списки их можно выбрать для настройки.

Группы не имеют Transform, не меняют IsActive или коллайдеры и игнорируются игровым рендером. Состав и видимость сохраняются в карте. Дублирование копирует принадлежность, восстановление удалённого объекта возвращает её.

### История и сохранение

Общая история включает трансформы, Inspector, Outputs, Environment, создание, удаление, дублирование и групповые операции. Непрерывное редактирование одного поля объединяется в шаг. Новое действие после Undo сбрасывает ветку Redo. Открытие или создание уровня очищает историю.

Undo удаления создаёт новый экземпляр по снимку, а не оживляет старый; предыдущие редакторские действия используют EditorObjectReference для доступа к восстановленному объекту. Для расширения редактора используйте SceneObjects.Create, Duplicate и Delete, чтобы сохранять историю и состояние изменений.

### Виды SceneView

В верхней панели рядом с Camera доступен список Perspective / Top / Front / Side. Все режимы используют один SceneView. Perspective сохраняет свободную камеру; Top смотрит сверху на XZ, Front — спереди на XY, Side — со стороны +X на ZY.

В ортографических видах средняя кнопка мыши перемещает вид по плоскости, колесо меняет масштаб, F центрирует выделенный объект и подбирает масштаб. Вращение камеры и полёт WASD отключены. При переключении вид ориентируется на выделение, а без выделения — на текущую точку обзора. Возврат в Perspective восстанавливает прежние положение и поворот камеры.

Сетка меняет плоскость вместе с видом. Выделение, Ctrl-выделение, перемещение, вращение, масштабирование и Resize BrushBox работают с текущей проекцией и общей историей Undo/Redo. Оси перемещения/масштаба, направленные прямо в камеру, не дают экранной ручки; соответствующие ручки Resize и кольца вращения, видимые строго с ребра, скрываются. Для изменения размера в направлении глубины переключитесь на другой вид. Режимы не меняют игровые камеры и данные уровня.

### Редактор ассетов сущностей

Edit → Entity Asset открывает отдельное окно описания сущности. New создаёт пустой черновик. В Class укажите полное имя конкретного наследника Entity и сборку, например ProjectShockGL.Placeables.LogicToggle, ProjectShockGL. Класс должен иметь публичный конструктор без аргументов.

Параметры задаются строками Key / Type / Value: String хранит обычный текст без JSON-кавычек, Number — число с точкой, Boolean — флажок, JSON — массив, объект или null. Например, DebugBillboard со значением Editor/Button имеет тип String. Add parameter добавляет строку, X удаляет её. Пустые и повторяющиеся ключи, неверный класс и некорректные значения отклоняются при сохранении.

Open выбирает JSON внутри Content/Entities. Save у нового ассета запрашивает путь в этой папке или её подпапках; повторный Save записывает открытый файл. При первом успешном сохранении назначается AssetId, последующие сохраняют тот же GUID. Идентификатор доступен только для чтения, Copy ID копирует его. Старый ассет без AssetId получает идентификатор при первом сохранении, без необходимости переписывать остальные ассеты. Уже существующий GUID при перезаписи сохраняется; если файл на диске получил другой GUID после открытия, сохранение отклоняется. New создаёт независимый черновик без идентификатора.

Изменения сохраняются отдельно от уровня. При New, Open или закрытии окна/редактора для изменённого ассета доступны Save / Discard / Cancel. После сохранения сбрасывается только кеш описания этого ассета в Content: новые размещения получают актуальные параметры, уже созданные объекты не пересоздаются. Неизвестные дополнительные поля открытого JSON сохраняются. В .map и префабах у сущностей сохраняется AssetId — GUID описания из Content/Entities. Он отличается от Guid экземпляра объекта. Path остаётся подсказкой, но при наличии AssetId поиск идёт по GUID во всех подпапках Entities. Переносите JSON с сохранением AssetId: новый файл на прежнем пути не подменит исходный ассет. Отсутствующий GUID или два ассета с одинаковым AssetId вызывают ошибку загрузки.

Старые карты и префабы без AssetId продолжают загружаться по Path. При сохранении уровня или нового префаба ссылки получают AssetId автоматически. Для перехода всего проекта используйте **Edit → Entity Asset → Fix Asset References** до перемещения файлов.

Команда проверяет все JSON в Content/Entities, уровни .map в Content/Levels и префабы JSON в Content/Prefabs, включая подпапки и старый однообъектный формат. Назначает недостающие GUID, сохраняет существующие и обновляет ссылки. При ошибках проверки (повреждённый JSON, неверный класс, GUID, повтор идентификатора или отсутствующая цель) ничего не записывает, включая резервные копии.

Перед записью создаются точные копии изменяемых файлов в AssetReferenceBackups/<дата-время-идентификатор> рядом с папкой Content. Отчёт показывает изменения, неизменённые файлы, ошибки и путь к копиям. Если запись прервана ошибкой, команда пытается вернуть уже заменённые файлы; ошибки восстановления тоже выводятся в отчёт. Повторный запуск не меняет уже обновлённые файлы и не создаёт лишних копий.

Команда работает с сохранёнными файлами. Несохранённый ассет сначала предложит Save / Discard / Cancel; открытый ассет после успешного обновления перечитывается. После успешного отчёта можно переносить JSON ассетов внутри Entities с сохранением AssetId. Geometry, Details, текстуры, имена Targets и строковые пути в игровом коде эта команда не меняет.

### Папки Scene

Scene использует общие папки для Entity, Geometry, BrushBox и Details. Внизу списка нажмите New folder, введите имя и нажмите Create. У папки нет Transform, Parent или игрового поведения; вложенные папки пока не поддерживаются.

Стрелка слева раскрывает или сворачивает папку. Щелчок по её имени выделяет всё содержимое; общий gizmo работает с этим выделением по обычным правилам. Объекты и Details можно выделять через Ctrl и перетаскивать вместе на имя папки. Чтобы вернуть их в корень, перетащите на строку Scene root. В контекстном меню папки доступны Move selected here, переименование через поле Name с подтверждением Enter и Delete folder (keep objects). Удаление папки оставляет её содержимое в корне Scene.

Каждое размещение может находиться только в одной папке. Groups остаются независимыми: они управляют видимостью и допускают несколько групп у одного объекта. Папки, их свёрнутое состояние и состав сохраняются в .map в массиве Folders; старые карты без него открываются с объектами в корне. Создание, переименование, удаление папок и перенос состава поддерживают Undo/Redo. Дубликаты остаются в папке оригиналов; удалённые и восстановленные через Undo объекты возвращаются в свои папки. Папки уровня не включаются в префаб: новые экземпляры префабов появляются в корне.

### Предпросмотр

Рамка выделения строится по локальному bound-у с учётом положения, поворота и масштаба объекта. Видимые рёбра белые, перекрытые непрозрачной геометрией — белые с альфой 0.2. Толщина фиксирована: 1.5 пикселя итогового framebuffer. Рамка рисуется после ResolutionScale и постобработки с проверкой перенесённой глубины мира, сама глубину не записывает и не меняется от тумана или цветовых эффектов. Она ограничена SceneView, скрыта под окнами редактора и отключена при открытом UI Editor. Поддерживаются множественное выделение и Details. Transparent-поверхности не записывают глубину и потому не приглушают рамку позади себя.


В правом верхнем углу SceneView показан неинтерактивный индикатор мировых осей X/Y/Z: красная X, зелёная Y, синяя Z. Стрелки ориентируются относительно поворота камеры редактора, независимо от выделения, режима Local и инструмента манипуляции. Индикатор не перехватывает мышь, скрывается при открытом UI Editor и не рисуется поверх окон ImGui. Переключение вида по нажатию пока не предусмотрено.

Lit/Unlit и Environment в верхней панели меняют только предпросмотр: Unlit убирает освещение, отключённый Environment убирает туман и делает Ambient предпросмотра белым. Они не изменяют настройки уровня. View → Post processing переключает постобработку редактора. Настройки самого окружения редактируются отдельно и сохраняются в map.

## Объекты уровня

| Тип | Применение |
| --- | --- |
| Geometry | Статичная модель и коллайдер из JSON-ресурса |
| BrushBox | Процедурная коробка для геометрии уровня |
| Entity | Именованный объект с Inputs, Outputs и свойствами логики |

### BrushBox

| Свойство | Значение |
| --- | --- |
| Size | Полный локальный размер коробки по XYZ |
| Texture | JPG/PNG из Textures или WhitePixel |
| Texture scale | Число повторений на мировую единицу |
| Color / Lit | Цвет и участие в освещении |
| Movable | Разрешает использовать brush как нестатичную цель движения |

Коллайдер соответствует размерам. Изменение Size или Scale сохраняет плотность текстуры; отдельный файл модели не нужен. Для стены `(4, 3, 0.25)` при Scale=1 означает ширину 4, высоту 3 и толщину 0.25.

У каждой грани можно переопределить текстуру, плотность UV по двум осям и смещение. Настройки можно задавать кодом или через окно Texture.

    brush.SetFace(BrushFace.PositiveZ, new BrushFaceData
    {
        Texture = "Walls/Concrete",
        TextureFormat = TextureFormat.Png,
        TextureScale = new Vector2(2, 1),
        TextureOffset = new Vector2(0.25f, 0)
    });

BrushFace и BrushFaceData находятся в ProjectShockGL.Core. Текстура указывается относительно Content/Textures без расширения. Грани названы по локальным осям: PositiveX / NegativeX, PositiveY / NegativeY, PositiveZ / NegativeZ. TextureScale задаёт число повторений на мировую единицу по U и V (больше значение — мельче текстура), TextureOffset — сдвиг UV: 1 означает один полный повтор. Масштаб должен быть положительным. Смещение может быть отрицательным.

Неуказанные Texture, TextureFormat и TextureScale наследуются от общих настроек BrushBox. Для сброса грани используйте brush.SetFace(BrushFace.PositiveZ, null). Faces позволяет читать настройки, CaptureFaces возвращает независимую копию, SetFaces заменяет весь набор. Настройки сохраняются в .map и префабы, копируются при дублировании и восстанавливаются историей редактора. Старые карты без Faces используют прежние общие настройки. Грани с одинаковой текстурой рисуются вместе; разные текстуры могут добавить вызовы отрисовки.

В редакторе откройте Edit → Texture или нажмите Texture... в Inspector браша. Пока окно открыто, щелчок в SceneView выбирает ближайшую грань BrushBox вместо обычного выделения и gizmo; выбранная грань обведена жёлтым. Также грань можно выбрать из списка Face. Закройте окно, чтобы вернуться к обычному выделению и манипулятору.

В Texture доступны выбор текстуры с папками и поиском, UV scale и UV offset. Use brush texture и Use brush UV scale возвращают наследование общих настроек. Fit сбрасывает смещение и устанавливает один полный повтор по ширине и высоте текущей грани с учётом Scale объекта. После Fit текстура остаётся повторяющейся, UV можно сдвигать и масштабировать. Reset face сбрасывает все переопределения грани. Назначение текстуры, Fit, сброс и изменение UV поддерживают Undo/Redo; одно перетаскивание значения — один шаг истории.

### Режим поверхности

MeshComponent, BillboardComponent и QuadComponent имеют SurfaceMode и AlphaCutoff. В Inspector настройки находятся в Properties; у объектов с несколькими игровыми компонентами они показываются для каждого отдельно. Debug-маркеры в этот список не входят.

| SurfaceMode | Поведение |
| --- | --- |
| Opaque | Игнорирует альфу текстуры и Color, рисует непрозрачную поверхность и записывает глубину |
| Cutout | Отбрасывает пиксели текстуры ниже AlphaCutoff; порог по умолчанию 0.5 |
| Transparent | Смешивает альфу текстуры и Color с фоном, проверяет глубину, но не записывает её |

В пределах одного RenderOrder сначала рисуются Opaque/Cutout, затем Transparent от дальних к ближним; IgnoreDepth-команды идут поверх. RenderOrder сохраняет приоритет явного порядка. Сортировка мешей идёт по центру их границ, билбордов — по позиции; пересекающиеся прозрачные меши могут потребовать разделения геометрии. Статический батчинг не объединяет Transparent, а для остальных учитывает режим и порог.

У BrushBox общий режим задаётся в Inspector. В Texture можно снять Use brush surface и переопределить режим или AlphaCutoff выбранной грани. Прозрачные грани отправляются отдельно для сортировки. Настройки сохраняются в .map и префабы, поддерживают дублирование и Undo/Redo. Старые карты без новых полей сохраняют прежний Cutout с порогом 0.5; значения компонентов, явно заданные в Create, при отсутствии сохранённого переопределения остаются в силе. Коллизия от режима поверхности не меняется.

    mesh.SurfaceMode = SurfaceMode.Transparent;
    billboard.SurfaceMode = SurfaceMode.Cutout;
    billboard.AlphaCutoff = 0.6f;

SurfaceMode находится в ProjectShockGL.Rendering. Для стекла используйте PNG с альфой либо Color с Alpha меньше 1. Обычные Lit/Unlit, SimplePBR и Lit-шаблон поддерживают режимы. Для собственного фрагментного шейдера рендерер передаёт uSurfaceMode (0 = Opaque, 1 = Cutout, 2 = Transparent) и uAlphaCutoff: отсечение выполняйте только при uSurfaceMode == 1, а в Opaque выводите альфу 1. Старые пользовательские шейдеры с жёстко заданным discard потребуется обновить. UI продолжает рисоваться с прежней прозрачностью.

### Связи префабов и дубликатов

При вставке префаба и дублировании выделенного набора движок сначала назначает свободные имена всем новым объектам, затем переназначает внутренние связи. Например, кнопка и дверь Button_1 → Door_1 превращаются в Button_2 → Door_2 при дублировании. При вставке префаба сохраняется прежний способ добавления суффикса: Door_1 может стать Door_1_1.

Автоматически обновляются OutputData.TargetName и сохранённые строковые свойства сущностей, отмеченные ObjectNameAttribute. Если цель не входит в создаваемый набор, ссылка остаётся внешней и сохраняет прежнее значение. При дублировании только кнопки её ссылка на нескопированную дверь также остаётся прежней. Замена выполняется по точному имени с учётом регистра, без поиска подстрок. Обычный текст не меняется.

~~~csharp
[Editable, ObjectName]
public string TargetName { get; set; } = "";
~~~

ObjectName находится в ProjectShockGL.Core и предназначен для public string-свойств вместе с Editable. Наследуемые свойства также поддерживаются. Уже отмечены LinearMovement.TargetName, Monitor.CameraName и Trigger.ObjectName. На собственный Object.Name, имена уровней и пути ресурсов атрибут не нужен. Строковые параметры Inputs, включая AttachTo и Setup, пока не переназначаются: Output.Parameter остаётся как записан.

Одинаковые имена внутри набора, включая несколько пустых имён, отклоняются до создания объектов; сохранение такого префаба тоже запрещено. Переименуйте объекты и повторите операцию. Исходный шаблон и исходные объекты не изменяются. Undo/Redo восстанавливает уже назначенные имена и связи. Смешанное дублирование объектов и Details использует те же правила для объектов. Для динамических экземпляров префабов таблица имён сохраняется с источником создания, чтобы восстановление из сохранения игры не возвращало ссылки к именам шаблона.

### Активность и статичность

- SetActive(false) исключает объект из обновления, отрисовки и физических запросов. Он остаётся доступен через World.Find. Выключенный свет не освещает сцену.
- IsStatic обозначает неизменное размещение уровня: объект всегда активен, в Inspector его IsActive включён и заблокирован. SetActive(false) игнорируется и в игре, и в редакторе. При переводе неактивного браша в статичный он включается.
- В игре статичному объекту нельзя менять Position, Rotation, Scale, снимать статичность или удалять его через Destroy()/World.Destroy(): попытки игнорируются. Начальный трансформ задаётся при загрузке размещения или после World.Spawn() до первого обновления мира, до Start. После этого размещение фиксируется. Выгрузка уровня и очистка при ошибке создания освобождают объекты независимо от статичности.
- Geometry всегда статична. Entity и её наследники не могут быть статичными: попытка присвоить IsStatic=true вызывает InvalidOperationException. BrushBox по умолчанию статичен; Movable=true при подготовке уровня делает его нестатичным. Для появления по триггеру, перемещения, удаления или включения физики в игре заранее используйте нестатичный объект.

В редакторе трансформ и размер статичной геометрии редактируются, объекты удаляются обычным способом. У статичного BrushBox в игре заблокированы также изменение Size и включение SimulatePhysics. Старые карты с IsActive=false у статичной геометрии загружаются с активной геометрией. Статичность по-прежнему пропускает обычный Update, позволяет кешировать границы и исключает проверки пар двух статичных коллайдеров. Для Geometry и статичных BrushBox с обычным Lit/Unlit в игре доступен статический батчинг.

Для управления brush по TargetName превращать его в Entity не требуется: поиск цели работает с Object. Параметр Movable сохраняется, дублируется и поддерживает Undo/Redo.

## Игровая логика

### Inputs и Outputs

| Поле Output | Назначение |
| --- | --- |
| Event | Имя события, отправляемого исходной сущностью |
| Target | Имя объекта в мире |
| Input | Имя метода с атрибутом Input |
| Parameter | Аргументы через запятую |

Имена целей должны быть уникальны: поиск возвращает первый подходящий объект. Числа записываются с точкой, bool — true/false. Outputs вызываются кодом через Entity.InvokeEvent; одно наличие строки в Inspector не создаёт событие автоматически.

`InvokeEvent("OnValueChanged", value)` передаёт одно динамическое значение. Совместимый Input с одним аргументом получает его вместо Parameter. Поддерживаются совпадающие типы, числовые преобразования и преобразование в строку. Число автоматически не становится bool. При несовместимости или нескольких аргументах используется Parameter; Input без аргументов вызывается без них.

### Своя сущность

Пример пользовательского класса в сборке MyGame:

```csharp
using ProjectShockGL.Core;

namespace MyGame.Placeables;

public class Switch : Entity
{
    [Editable] public bool Locked { get; set; }

    [Input("Use")]
    public void Use()
    {
        if (!Locked) InvokeEvent("OnUsed");
    }
}
```

Сохраните Content/Entities/Logic/Switch.json:

```json
{
  "Class": "MyGame.Placeables.Switch, MyGame",
  "Parameters": {}
}
```

После подключения сборки и обновления Palette ресурс доступен в категории Logic. Это пример логики без модели. Изображение и коллайдер создаются отдельно в Create через компоненты. Parameters — данные ресурса для Entity.Load(Dictionary<string, object>); Editable-свойства экземпляра сохраняются в карте отдельно.

## Объекты, компоненты и жизненный цикл

Application создаёт окно и вызывает события цикла. Game владеет World и sealed UIManager. World создаёт, обновляет и удаляет Object. Объект содержит Transform, компоненты, активность и маски столкновений; Entity расширяет его ресурсом и связями уровня.

1. World.Spawn сразу вызывает Create: здесь создавайте компоненты и подготавливайте объект.
2. Загрузчик назначает свойства и трансформ из карты.
3. При активном игровом обновлении вызывается начальный OnActiveChanged(true), затем Start.
4. Start вызывается один раз; у изначально выключенного объекта откладывается до первого активного обновления.
5. Активный нестатичный объект получает Update. Повторное включение не повторяет Start.
6. Уничтожение останавливает корутины и освобождает компоненты. Уничтоженный объект повторно не включается.

В переопределениях вызывайте базовый метод, чтобы сохранить обслуживание компонентов. Используйте World.Destroy для удаления, World.Clear для полной очистки. Cleanup выполняет все заданные операции освобождения, собирая ошибки; ошибка одной операции не должна оставлять остальные ресурсы без очистки.

В редакторе выполняется Create, загрузка свойств и отображение, но не игровая активация, Start, Update или корутины. Не размещайте запуск таймеров и игровой сценарий в Create. World.Find<T>() и Find(name) видят также созданные объекты, ожидающие Start.

### Доступ к своему World

У Object есть публичное свойство World только для чтения. Внутри объекта можно писать World.Destroy(obj), World.Spawn<T>() и World.Find(name), обращаясь к фактическому владельцу объекта, а не Game.Instance.World. Ссылка назначается до Create. У объекта, созданного через new без World.Spawn, а также после удаления или начала очистки мира обращение к World вызывает InvalidOperationException. Для уничтожения самого себя по-прежнему можно вызвать Destroy().

### AttachTo и Detach

Object поддерживает прикрепление к другому объекту текущего World. Связь создаётся игровым кодом или Inputs, без отдельного раздела Inspector и без сохранения в map или префабе.

~~~csharp
camera.AttachTo(box);     // Прикрепить с сохранением мирового положения и вращения.
camera.AttachTo("Box");   // Найти цель по Name в своём World.
camera.Detach();          // Открепить, оставив текущие мировые положение и вращение.
~~~

В Output у BeginPlay выберите имя камеры в Target, AttachTo в Input и имя коробки в Parameter. Для открепления: Target — камера, Input — Detach, Parameter пустой. Имена целей должны быть уникальны; отсутствующая цель даёт предупреждение и не изменяет существующую связь.

Смещение рассчитывается относительно положения и вращения цели. Её Scale не влияет ни на размер прикреплённого объекта, ни на расстояние до него. Изменение мировых Position или Rotation прикреплённого объекта пересчитывает его смещение; повторный AttachTo меняет цель без скачка. Текущая цель доступна в AttachmentTarget. Поддерживаются цепочки связей без циклов.

Трансформы прикреплённых объектов обновляются сразу при изменении трансформа цели, включая обновление из Bepu. Поэтому камера получает итоговое положение коробки до SynchronizeComponents и захвата RenderTexture; отдельное игровое обновление или новая стадия цикла для Attach не нужны. При уничтожении цели объекты открепляются на месте; активность объектов не наследуется.

Прикрепляемый объект должен быть нестатичным, без включённого Rigidbody. У цели Rigidbody может работать. Чтобы включить Rigidbody у прикреплённого объекта, сначала вызовите Detach. Добавление включённого Rigidbody и включение IsStatic во время прикрепления запрещены. Объекты из разных World, уничтоженные объекты, прикрепление к себе и циклы отклоняются. При загрузке уровня связь заново создаёт логика уровня через Outputs или код.

### Уничтожение ниже уровня

World.KillY задаёт общий нижний порог по мировой координате Y (по умолчанию -1000). При Position.Y < KillY у активной Entity вызывается виртуальный Kill(), который по умолчанию вызывает Destroy(). Порог задаётся полем Kill Y в окне Environment и сохраняется в поле KillY файла уровня. Изменение поддерживает Undo/Redo. Reset to defaults возвращает -1000. При загрузке старых карт без поля используется -1000, а не значение предыдущего уровня. Из игрового кода порог доступен через World.KillY.

Проверка выполняется после обновлений и корутин мира при положительном игровом шаге, для активных Entity. Обычные Object и геометрия не затрагиваются. В редакторе, при simulate=false и на паузе автоматического вызова нет. Переопределите Kill() для смерти персонажа или возврата на безопасную позицию; base.Kill() уничтожит сущность. Если переопределение оставляет её ниже границы, вызов не повторяется каждый кадр: сущность должна вернуться к границе или выше, чтобы следующее падение снова вызвало Kill().

### Отладочная отрисовка

DebugBillboard и DebugMesh из параметров Entity рисуются поверх сцены с IgnoreDepth. Эти компоненты создаются только при наличии соответствующего параметра и не подменяют игровой MeshComponent. В редакторе сетка рисуется в RenderOverlayBackground перед debug-маркерами; игровой мир, сетка и маркеры имеют отдельный порядок отрисовки. Сетка не зависит от тумана и освещения уровня, следует за камерой по XZ и остаётся привязанной к мировым координатам. Радиус области — 500 единиц: до расстояния 50 линии чёткие, далее плавно исчезают к 500. Сетка рисуется одним quad со сглаживанием линий постоянной толщины по покрытию пикселя, учитывает глубину сцены, не записывает собственную глубину и восстанавливает состояние прозрачности и отсечения граней. Минимальный видимый шаг и Move step — 0.01. Толщина линий составляет 4% шага; когда размер клетки на экране уменьшается с четырёх пикселей до одного, обе группы линий и оси плавно скрываются вместе, не образуя заливку. Привязка объектов продолжает использовать выбранный шаг даже при скрытых мелких линиях. Show Grid работает как прежде.

Object и Component имеют виртуальные методы DebugRender(DebugDraw draw) и DebugRenderSelected(DebugDraw draw). Первый вызывается в редакторе и в игре при Application.IsDebug (IsDebug=true в разделе Application файла настроек). Второй дополнительно вызывается только в редакторе для каждого выделенного объекта и его компонентов, включая множественное выделение. Базовый метод для обслуживания компонентов вызывать здесь не требуется: движок вызывает их отдельно.

DebugDraw находится в ProjectShockGL.Rendering. Доступны Line(from, to, color), Box(position, rotation, size, color), Sphere(position, radius, color) и Billboard(position, size, texture, color). Координаты мировые, size куба — полный размер. Куб каркасный, сфера изображается тремя окружностями. Билборд обращён к текущей камере и имеет размер в мировых единицах. Последний необязательный параметр ignoreDepth=true позволяет рисовать поверх стен. Примитивы не освещаются и рисуются после постобработки мира, до UI.

```csharp
public override void DebugRenderSelected(DebugDraw draw)
{
    draw.Box(Transform.Position, Transform.Rotation,
        new Vector3(2f, 1f, 2f), Color.White);
    draw.Line(Transform.Position, Transform.Position + Transform.Forward * 2f,
        Color.White, ignoreDepth: true);
}
```

Отладочная отрисовка не запускает Start или Update. В редакторе она доступна для неактивных объектов и отключённых компонентов; скрытые Groups и уничтоженные объекты исключаются. В игре рисуются только активные объекты и включённые компоненты. Методы предназначены для рисования, игровую логику в них размещать не следует. Существующие отладочные RenderComponent и манипуляторы редактора продолжают работать отдельно.

### Загрузка уровня

LevelManager.Load("MyLevel") читает Levels/MyLevel.map; можно передать Level. Доступны Loading/Loaded/Unloading/Unloaded, ActiveLevel, IsLoading и Unload(). В Loaded объекты и Environment уже назначены, но Start ещё не выполнен — здесь удобно создавать игрока.

Для перехода с выбором входа используйте LevelManager.Load("MyLevel", 2). На целевом уровне разместите PlayerStart с Index=2: Oxygen выберет среди таких точек наибольший Priority и возьмёт позицию и поворот. Индекс текущего входа доступен через LevelManager.EntryIndex. Обычный Load без индекса задаёт EntryIndex=-1 и сохраняет выбор общей точки с наибольшим Priority. Если заданного индекса нет, выводится предупреждение и используется общая стартовая точка; без PlayerStart остаётся прежнее появление в начале координат. При ошибке подготовки уровня индекс предыдущего уровня сохраняется. Unload сбрасывает его в -1. Для вызова из своей сущности Input можно вызвать ту же перегрузку Load с именем уровня и заранее настроенным индексом; обычное UI-действие Level/Load продолжает принимать одно имя уровня. При загрузке сохранения Oxygen использует сохранённые позицию и поворот, а не точку входа.

У сущности LevelLoader параметр EntryIndex задаётся в Inspector: 2 означает вход через PlayerStart с Index=2, а -1 сохраняет обычный выбор без фильтра. В Output выберите LevelLoader в Target, Input=Load и укажите имя целевого уровня в Parameter. Индекс берётся из настроек самого LevelLoader; формат параметра Input не меняется. EntryIndex сохраняется в .map и префабы и поддерживает Undo/Redo; старые LevelLoader без этого поля используют -1.


Загрузка синхронная и подготавливает новый мир до замены старого. Вложенные переходы из обработчика загрузки запрещены. Подписки на события нужно снимать при Unload; пример находится в [ProjectDungeon/Core/Game.cs](ProjectDungeon/Core/Game.cs).

### Камеры и CameraComponent

Application при инициализации окна создаёт запасную Camera.Default, которая не принадлежит World и сохраняется при смене уровня. Camera.Active — текущая камера. Camera.UseDefault() явно возвращает запасной вид. В редакторе запасной камерой управляет SceneCamera.

Для камеры игрового объекта добавьте CameraComponent в Create:

```csharp
_cameraComponent = AddComponent<CameraComponent>();
_cameraComponent.LocalPosition = new System.Numerics.Vector3(0, 0.6f, 0);
```

В игровом Start настройте `_cameraComponent.Camera.Fov` (радианы), Near/Far и остальные параметры, затем вызовите `_cameraComponent.MakeActive()`. Создание компонента само по себе вид не переключает. MakeActive возвращает false для выключенного/уничтоженного владельца или компонента, освобождённой камеры и в режиме редактора.

LocalPosition задаётся в локальных координатах владельца с учётом его масштаба и вращения. LocalRotation — локальный Quaternion; мировое вращение равно Owner.Rotation * LocalRotation. Например, персонаж вращает свой объект по yaw, а наклон взгляда задаёт через LocalRotation камеры. Компонент владеет отдельным экземпляром Camera; запись в Camera.Active не требуется.

Камеры автоматически синхронизируются непосредственно перед отрисовкой в Application, после завершения обновления игровой логики и физики. В Game.Update синхронизация не выполняется. Если игровому коду нужен актуальный трансформ раньше, вызовите Synchronize(). Отключение IsEnabled, SetActive(false), удаление компонента, уничтожение владельца или выгрузка уровня возвращают активный вид к Camera.Default. Уничтожение неактивной камеры не переключает текущий вид. Повторное включение само по себе не активирует камеру: вызовите MakeActive явно. Персонажи примера и ProjectA делают это при повторном включении.

FramebufferResize обновляет пропорции запасной и активной камеры; при переключении неактивная получает актуальный AspectRatio. Нулевой framebuffer при сворачивании игнорируется. Camera.Create/ToggleTo остаются низкоуровневым API, но для камер объектов используйте компонент, чтобы жизненный цикл был связан с владельцем.
### Камера наблюдения и RenderTexture

CameraCaptureComponent наследует CameraComponent: у него есть Camera, LocalPosition и LocalRotation. Перед основной камерой Application запускает захваты текущего World. Они не переключают Camera.Active, не обновляют игровую логику повторно и рисуют только мир: обычные меши, статические батчи и Details, без UI, отладочного рендера и общей постобработки. Освещение, туман и SkyColor берутся из Environment. Захваты работают и в редакторе; выключенный компонент, неактивный объект и скрытая редакторская группа не захватывают изображение, сохраняя последний кадр.

Пример настройки в Create сущности камеры:

~~~csharp
public CameraCaptureComponent Capture { get; private set; } = null!;

public override void Create()
{
    base.Create();
    Capture = AddComponent<CameraCaptureComponent>();
    Capture.SetResolution(256, 192);
    Capture.Filter = RenderTextureFilter.Nearest;
    Capture.Camera.Fov = MathF.PI / 3;
    Capture.LocalPosition = new Vector3(0, 1.5f, 0);
}
~~~

После создания объектов можно подключить экран монитора:

~~~csharp
var screen = monitor.GetComponent<MeshComponent>()!;
screen.Texture = securityCamera.Capture.Texture;
screen.Lit = false;
~~~

Здесь monitor — объект с мешем экрана, securityCamera — экземпляр сущности из примера. Размещайте камеру трансформом её владельца. Несколько мониторов могут использовать одну Texture. RenderTexture выдаёт изображение с той же ориентацией UV, что и обычная загруженная текстура; вручную переворачивать его не нужно. Меши, использующие текстуру текущего захвата, в этом захвате пропускаются. Рекурсивный захват не поддерживается.

По умолчанию разрешение 256x192, фильтрация Nearest. Linear даёт более мягкое увеличение. SetResolution(width, height), Width, Height и Filter можно менять в игре: ссылка на Texture и её GPU handle сохраняются, поэтому переназначать текстуру экранам не нужно. Соотношение сторон проекции на время захвата соответствует разрешению RenderTexture. Отключение через IsEnabled останавливает обновление; Destroy компонента или выгрузка World освобождает его камеру, текстуру и framebuffer. Не освобождайте Capture.Texture или Capture.Target вручную — ими владеет компонент.

Для ручного захвата есть Content.CreateRenderTexture(width, height, filter) и target.Capture(world, camera). Такой RenderTexture не попадает в кеш Content; вызывающий код обязан освободить его через Dispose. Создание, изменение размеров, захват и освобождение выполняются в потоке OpenGL после инициализации Content. Статистика прохода доступна через Target.Statistics; основная экранная статистика draw calls пока не включает отдельные захваты. Каждый включённый компонент добавляет отдельную отрисовку мира. Эффекты захвата пока не добавлены; настройки размещаемых камер описаны ниже.

### Размещаемые камеры

В Palette → Entity → Placeables доступны Camera (класс CameraEntity) и CameraCapture (класс CameraCaptureEntity). Их ассеты находятся в StarterContent/Entities/Placeables; для своей папки Content скопируйте эти JSON и текстуру Editor/Entity.png из StarterContent. В Content ProjectA ассеты уже добавлены.

Обе сущности имеют настройки FieldOfView (в градусах), NearClip, FarClip, Orthographic, OrthoSize и ClearColor. Положение и направление задаются Transform; при выделении жёлтая стрелка показывает взгляд вдоль локальной -Z. При включённом Environment.SkyColorEnabled цвет фона берётся из Environment, а не ClearColor камеры.

Camera не становится активной при создании или загрузке уровня. Назовите её в Inspector и переключайте из игрового кода или через Input MakeActive:

~~~csharp
if (World.Find("ViewCamera") is CameraEntity camera)
{
    camera.MakeActive();
}
~~~

MakeActive возвращает bool; в редакторе и для выключенной камеры он возвращает false. Input ReleaseActive возвращает запасную камеру, если именно эта камера сейчас активна. Отключение или уничтожение активной камеры также возвращает запасную.

У CameraCapture дополнительно редактируются Width, Height и Filter (Nearest / Linear). Разрешение по умолчанию 256x192; параметры сохраняются в map, префабах и истории Inspector. Width и Height задаются в пикселях, значения меньше 1 ограничиваются единицей; при создании GPU-ресурсов разрешение проверяется по возможностям видеокарты. Камера наблюдения автоматически захватывает мир, не переключая активную камеру. Результат доступен как entity.Texture или entity.Capture.Texture. При изменении разрешения ссылка на Texture сохраняется. Для вывода на поверхность используйте Monitor.

### Monitor

В Palette → Entity → Placeables доступен Monitor (ProjectShockGL.Placeables.Monitor). Это односторонний Unlit-квад размером 1x1 без коллайдера. Лицевая сторона направлена вдоль локальной +Z; ширина и высота задаются Transform.Scale.X и Transform.Scale.Y. Разрешение захвата не меняет размер и пропорции квада: изображение растягивается на всю поверхность, а пропорции подгоняются вручную через Scale.

В Inspector задайте CameraName — Name сущности CameraCapture на текущем уровне, а не путь к её ассету. Имя сохраняется в map и префабах, поддерживает историю Inspector и дублирование. В игре начальное подключение происходит в Start, когда все объекты уровня уже созданы; в редакторе изменение CameraName применяется при отрисовке предпросмотра.

~~~csharp
if (World.Find("HallMonitor") is ProjectShockGL.Placeables.Monitor monitor)
{
    monitor.Setup("HallCamera");
}
~~~

Через Outputs выберите монитор в Target, Setup в Input и имя камеры в Parameter. Повторный Setup позволяет сменить источник или повторить поиск после создания камеры. Пустое имя, отсутствующая цель или цель другого класса дают чёрный экран; при явном Setup с непустым неверным именем выводится предупреждение. Уничтожение камеры или её компонента также даёт чёрный экран. Отключение захвата сохраняет последний кадр камеры.

Несколько мониторов используют одну текстуру захвата. Monitor не освобождает её при уничтожении: ею владеет CameraCaptureComponent. Квад создаётся движком и хранится в Content до очистки кеша; дополнительные модели и текстуры для Monitor не нужны.

## Время, таймеры и корутины

### Источники времени

Текущий API находится в [Time.cs](ProjectShockGL/Time.cs), а не в Application:

| Член Time | Назначение |
| --- | --- |
| DeltaSeconds | Шаг кадра с учётом TimeScale |
| UnscaledDeltaSeconds | Независимый шаг кадра |
| ElapsedTime | Накопленное игровое время |
| UnscaledElapsedTime | Накопленное независимое время |
| TimeScale | 1 — обычная скорость, 0.5 — замедление, 0 — остановка игрового времени |

Application.AdvanceTime вычисляет эти значения из времени окна. Отрицательный или нечисловой TimeScale запрещён. Масштаб времени сам по себе не отключает ввод и произвольную логику.

Core.Game.Update масштабирует реальный шаг кадра один раз: `deltaSeconds * Time.TimeScale`. World, корутины и игровые таймеры получают игровой шаг; независимые задержки и UI — исходный шаг кадра. При TimeScale=0 игровой отсчёт стоит, независимый продолжается. Объекты получают Update с нулевым шагом, поэтому ввод и действия, не зависящие от времени, сами по себе не блокируются.

### Timer

```csharp
using Timer = ProjectShockGL.Core.Timer;

var timer = new Timer(useUnscaledTime: true);
timer.Finished += () => Console.WriteLine("Готово");
timer.Run(2f);
// Храните timer у владельца; при уничтожении владельца вызовите timer.Dispose().
```

В игровом объекте храните таймер в поле и вызывайте Dispose при уничтожении. Его обновляет менеджер из Game; сам Timer не является объектом мира.

- Run запускает или перезапускает без повторных подписок.
- SetRemainingSeconds меняет остаток, RemainingSeconds читает его.
- SetPaused приостанавливает; IsRunning() остаётся true, IsPaused сообщает о паузе.
- Stop отменяет без Finished; Complete завершает работающий таймер с событием.
- При завершении остаток равен 0; сначала ValueChanged(0), затем Finished. Перезапуск или отмена из ValueChanged подавляет устаревший Finished.
- Dispose освобождает подписки; повторное использование запрещено.

### Coroutine

Методы Object: StartCoroutine(IEnumerator), StopCoroutine(handle), StopAllCoroutines(). У выполнения доступны Stop(), IsCompleted и IsCancelled.

Пример метода внутри нестатичного наследника Object/Entity, с using System.Collections и System.Numerics:

```csharp
private IEnumerator Raise()
{
    yield return new WaitForSeconds(0.3f, useUnscaledTime: true);
    var start = Transform.Position;
    var target = start + new Vector3(0, 2, 0);
    var elapsed = 0f;
    while (elapsed < 1f)
    {
        yield return null;
        elapsed += ProjectShockGL.Time.UnscaledDeltaSeconds;
        Transform.Position = Vector3.Lerp(start, target, Math.Clamp(elapsed, 0f, 1f));
    }
    Transform.Position = target;
}
// Запуск из игрового метода: StartCoroutine(Raise());
```

Для игрового времени используйте WaitForSeconds(seconds) и Time.DeltaSeconds в анимации; для независимого — useUnscaledTime=true и UnscaledDeltaSeconds. Это прямое изменение трансформа, без проверки пути на столкновения.

StartCoroutine сразу выполняет код до первого ожидания. null и нулевая задержка ждут следующего обновления. Можно возвращать вложенный IEnumerator или Coroutine. Продолжение выполняется после обновления объектов мира, до TimerManager и Physics. Точность ожиданий ограничена кадром.

Неактивный владелец приостанавливает выполнение, включение продолжает. Уничтожение, Stop и выгрузка мира отменяют последовательности с освобождением вложенных итераторов и выполнением finally. Корутины статичных объектов тоже обслуживаются; в редакторе запуск запрещён. Ошибка одной корутины журналируется и завершает её. Это не потоки: тяжёлый код без yield блокирует кадр.

## Физика и персонаж

Поддерживаются BoxCollider, SphereCollider и CapsuleCollider, триггеры, Enter/Exit, слои и запросы Raycast/OverlapSphere/OverlapSphereAll/OverlapCapsule. PhysicsQueryFilter позволяет исключить IgnoreObject, IgnoreCollider и IgnoreTriggers. Для движения и запросов учитывайте маски слоёв; для событий столкновений проверяются CollidesWith обеих сторон.

CharacterController — капсула с Move(displacement), а не полноценное физическое тело. Метод принимает смещение за кадр; гравитацию и скорость определяет игра. Доступны SkinWidth, CollisionMask, StepOffset, SlopeLimit, IsGrounded, GroundNormal, CollisionFlags и LastDisplacement.

После движения объектов Physics.Update вытесняет даже стоящего персонажа из твёрдых коробок, сфер и капсул. Собственные коллайдеры, триггеры и выключенные объекты исключаются. Используется skin-допуск и ограниченное число попыток; после коррекции обновляется опора. LastDisplacement относится к последнему явному Move.

Нет масс и сил, переноса персонажа платформой или политики зажатия дверью. Объект, целиком прошедший через персонажа за кадр, может остаться незамеченным. При нулевом игровом шаге базовый Game пропускает автоматический Physics.Update; явные запросы остаются доступны.

## Отображение

### Свет и окружение

Light поддерживает Directional, Point и Spot. Inspector показывает редактируемые параметры света, включая Color, Intensity, Radius и внутренний/внешний углы конуса Spot (InnerAngle/OuterAngle); реализация в [Light.cs](ProjectShockGL/Core/Light.cs). Выбранный Point показывает радиус, Spot — конус, Directional — направление. Свет выключенного объекта не участвует в сцене.

Environment хранит SkyColorEnabled, SkyColor, AmbientColor, IsFogEnabled, FogColor, FogNear и FogFar; редактор сохраняет их в map, загрузчик применяет при смене уровня. При SkyColorEnabled цвет очистки берётся из SkyColor, иначе — из ClearColor активной камеры. По умолчанию SkyColorEnabled выключен. Отключение Environment в предпросмотре редактора также возвращает цвет камеры. Динамических теней и запекания света нет.

### Detail: декоративные размещения и instancing

Detail не наследуется от Object: у него нет компонентов, активности, коллайдера, Outputs и собственного жизненного цикла. Реализованы данные, коллекция World, сохранение/загрузка карт и отрисовка через instancing. Details доступны в Palette, SceneView и Inspector; размещения поддерживают перемещение, вращение и масштабирование через общий gizmo.

DetailAsset загружается через Content.LoadDetail("ExampleCube") из Content/Details/ExampleCube.json. Описание содержит Mesh и Texture (имена без расширений), TextureFormat (Jpeg/Png), Color в виде [R,G,B,A], Lit и BackfaceCulling. По умолчанию Texture=WhitePixel, Color белый, Lit и BackfaceCulling включены. Content.LoadDetail кеширует только JSON-описание; при первой отрисовке DetailRenderer загружает меш и текстуру через Content. Пример есть в StarterContent/Details/ExampleCube.json.

DetailPlacement содержит Id, AssetPath, Position, Rotation, Scale и EditorGroups. Id сохраняется в карте; активность и физические параметры отсутствуют. Свойства задаются при создании записи, EditorGroups копируются и доступны только для чтения. Коллекция World.Details поддерживает Add, Find, Update, Remove, Clear, Count, индексатор, перебор и Revision для отслеживания изменений. Для Update передайте новую запись с прежним Id.

Например, при подготовке мира до первого Update:

    var detail = World.Details.Add(new DetailPlacement
    {
        AssetPath = "ExampleCube",
        Position = new Vector3(2, 0, -4),
        Scale = new Vector3(0.5f)
    });

После загрузки карты или первого игрового обновления коллекция фиксируется: Add/Update/Remove/Clear вызывают InvalidOperationException. В редакторе редактирование разрешено. World.Clear и выгрузка уровня очищают данные служебным путём.

В .map размещения записываются в отдельный массив Details рядом с Placeables. CaptureCurrentLevel и SaveCurrentLevel сохраняют весь набор, а CaptureLevel для выбранных объектов не подмешивает Details в префабы. Старые карты без Details получают пустую коллекцию. Ошибки в описании ассета, дубли Id или некорректные трансформы отклоняют загрузку до замены текущего мира. Details не входят в сохранение игрового состояния по GUID объектов.
В Palette выберите Details: категории берутся из подпапок Content/Details, доступен поиск. Выберите ассет и нажмите Create — размещение появляется в начале координат и выделяется. Создание можно отменить через общий Undo/Redo. Для теста можно скопировать StarterContent/Details/ExampleCube.json вместе с указанными в нём ресурсами в Content игры.

В Scene размещения перечислены в отдельной ветке Details. Их можно выбирать и в SceneView по bounds исходного меша, в том числе перебором повторных щелчков. Ctrl добавляет или убирает размещение; поддерживается общее выделение объектов и Details. Move/Rotate/Scale работают с общим pivot, Local, Snap и временным Snap по Shift. Esc отменяет перетаскивание, Undo/Redo восстанавливают трансформ одним шагом. Отрицательный масштаб Detail сохраняет знак при масштабировании.

Inspector одиночного Detail показывает Transform и ссылку Asset, которую можно заменить через список с папками и поиском. Изменение трансформа и ассета поддерживает Undo/Redo; Id и EditorGroups сохраняются. IsActive, физика и Outputs не показываются. Focus/F приближает камеру к bounds размещения. Для нескольких выбранных элементов Inspector сообщает, что множественное редактирование недоступно, но общий gizmo работает.

Ctrl+D и Delete, меню Edit и кнопки Inspector дублируют и удаляют Details. Для смешанного выделения действие применяется ко всему набору и отменяется одним шагом Undo/Redo. Копия Detail получает новый Id; Undo/Redo восстанавливают прежние Id, трансформы, ассеты, членство в группах, порядок и выделение. Старые записи истории трансформов и групп продолжают работать после восстановления удалённого размещения.

Панель Groups считает и показывает обычные объекты и Details. Add selected и Remove selected изменяют членство всего выделения одним шагом истории; Remove рядом со строкой убирает одного участника. Скрытие группы влияет только на редактор, не меняет IsActive объектов и не удаляет размещения. Delete group удаляет группу и её связи с объектами и Details; Undo возвращает связи и видимость. Все эти данные сохраняются в .map.

Кисть пока не добавлена. В сохранённой карте размещения продолжают быть данными DetailPlacement, а не Object.
Отрисовка Details выполняется в проходе мира и учитывает освещение, туман, ResolutionScale и постобработку. Совпадающие Mesh, Texture, Color, Lit и BackfaceCulling объединяются в группы: одна группа использует один меш и один GPU-буфер трансформов, а не копии геометрии для каждого размещения. Debug-статистика учитывает один draw call на группу и треугольники всех экземпляров.

InstancedLit.vert и InstancedUnlit.vert используют матрицу экземпляра; обычные Lit.frag и Unlit.frag остаются общими. Неравномерный масштаб учитывается обратной транспонированной матрицей нормалей. Поддерживаются BackfaceCulling и переключатели Unlit/Environment редакторского предпросмотра. Пользовательские шейдеры Details пока не предусмотрены.

Буферы переиспользуются, пока Revision коллекции и редакторская видимость Groups не меняются. В игре Groups не скрывают Details. World.Clear и выгрузка уровня освобождают буферы экземпляров и их VAO; общие меши, текстуры и программы остаются у Content до его очистки. Details не участвуют в статическом объединении мешей. Отсечение экземпляров по камере и сортировка полупрозрачных экземпляров пока не реализованы.
### Статический батчинг

В игре Geometry и статичные BrushBox с обычным Lit/Unlit автоматически объединяются при отрисовке. Совпадать должны текстура, Color, Lit, BackfaceCulling и RenderOrder. Объекты с пользовательским Shader, IgnoreDepth, прозрачным Color или текстурой с прозрачными пикселями рисуются отдельно. Entity и подвижные браши не объединяются. Несовместимая команда прерывает объединяемую последовательность, чтобы не переносить геометрию через другие проходы отрисовки.

Вершины переносятся в мировые координаты с учётом трансформа объекта и настроек MeshComponent; UV сохраняются, нормали преобразуются обратной транспонированной матрицей. Обычный Lit использует такое же преобразование нормалей. Батчи создаются при первой отрисовке и переиспользуются; изменение меша через UpdateVertices, состава команд или настроек обновляет затронутые группы. Одиночный подходящий меш рисуется без дополнительной копии.

Объекты, GUID и коллайдеры остаются отдельными. Батчи принадлежат World и освобождаются при Clear/выгрузке уровня. В редакторе объединение отключено. Для сравнения draw calls и изображения можно временно задать Game.Instance.World.StaticBatchingEnabled = false; это не настройка карты.

Это объединение мешей, не instancing: память под исходные и объединённые меши сохраняется, а CPU-копии вершин и индексов нужны для сборки. Пространственное разбиение батчей и отсечение их по камере пока не реализованы.
### Шейдер объекта

Назначайте программу RenderComponent; отдельная система материалов не требуется:

```csharp
mesh.Shader = Content.LoadShaderProgram("Deform", "Lit");
mesh.ShaderParameters.Set("uAmplitude", 0.15f);
```

Здесь mesh — ваш MeshComponent, а Deform.vert/Lit.frag находятся в Shaders. Параметры поддерживают float/int/bool, Vector2/3/4, Color и Matrix4x4. Remove и Clear удаляют переопределения. Имена uniform должны соответствовать GLSL; матрицы, текстура, освещение и прочие служебные значения передаются рендерером.

В ресурсах примера есть [Deform.vert](StarterContent/Shaders/Deform.vert) и [Pulse.frag](StarterContent/Shaders/Pulse.frag). Для Pulse можно использовать пару Unlit/Pulse и параметры uPulseColor, uPulseSpeed, uPulseStrength. Деформация изображения не изменяет физический коллайдер и границы объекта.

### SimplePBR: упрощённое освещение поверхности

В Content примера добавлен Shaders/SimplePBR.frag. Он совместим с Lit.vert и Deform.vert, Directional/Point/Spot Light, Ambient, туманом, цветом и текстурой объекта. Обычный Lit не заменяется. Назначение MeshComponent:

```csharp
mesh.Shader = Content.LoadShaderProgram("Lit", "SimplePBR");
mesh.ShaderParameters.Set("uRoughness", 0.6f);
mesh.ShaderParameters.Set("uMetallic", 0.0f);
```

Roughness задаёт шероховатость (0..1, для устойчивости вычислений минимум ограничен 0.08), Metallic — долю металлического поведения (0..1). Значения по умолчанию: 0.6 и 0.0. Параметры отдельных объектов не переносятся на следующие отрисовки.

Модель использует GGX-блик, Schlick Fresnel и уменьшение диффузной составляющей для металлов. Радиусы, затухание и конусы света соответствуют существующему освещению движка. Unlit-предпросмотр показывает исходный цвет без освещения. Alpha cutout и туман работают по соглашению Lit.

Это PBR-подобное прямое освещение, без карт roughness/metallic, normal maps, отражений, карт окружения, IBL и отдельного HDR/sRGB-конвейера. Ambient применяется только к неметаллической диффузной составляющей: металл без прямого света может быть чёрным. Яркость и блики отличаются от обычного Lit; начните с Metallic=0 и подберите Roughness. Нормали поступают из выбранного вершинного шейдера; SimplePBR.frag не меняет его обработку неравномерного масштаба.

Проверка компиляции и изображения в скрытом OpenGL-окне: `dotnet run --project tests/PostProcessingChecks -- . --simple-pbr`.
### Постобработка

Профили — JSON в PostProcessProfiles. Пример собственного профиля:

```json
{
  "Enabled": true,
  "VertexShader": "PostProcess",
  "FragmentShader": "PostProcess",
  "Parameters": {
    "uVignetteStrength": 0.45,
    "uVignetteRadius": 0.6,
    "uVignetteSoftness": 0.5,
    "uGrainStrength": 0.0,
    "uGrainSize": 1.0,
    "uChromaticAberrationPixels": 0.0
  }
}
```

```csharp
ProjectShockGL.Rendering.PostProcessSettings.Apply("Default");
```

Профиль копирует параметры в активное состояние с преобразованием типов по uniform шейдера. Ошибка применения не должна частично заменить активный профиль. Можно загрузить описание через Content.LoadPostProcessProfile и передать его в Apply. Ресурсы кешируются; изменение JSON на диске требует перезапуска или выгрузки Content.

Эффект применяется к миру. UI, редакторский интерфейс и overlay рисуются после него. Доступны виньетка, film grain и chromatic aberration; их сила задаётся профилем. Нулевые значения отключают соответствующие эффекты; текущий Default в примере игры может использовать ненулевые значения. Bloom отсутствует.

## UI и текст

Game создаёт один sealed UIManager. Он создаёт один Canvas по Game/UICanvasClass; без настройки используется обычный Canvas. HUD, инвентарь и терминалы можно организовать как дочерние панели одного Canvas.

Canvas.Add<T>() создаёт корневой Widget, Widget.Add<T>() — дочерний. У корневого виджета Parent=null, но Canvas задан. SetParent меняет размещение внутри Canvas. RectTransform предоставляет Position, Size, Anchor, Pivot и вычисленную AbsolutePosition; ось Y интерфейса направлена вниз.

Виджет имеет Visible, IsEnabled и HitTestVisible. Жизненный цикл UI: OnCreate, OnUpdate, OnDraw, OnDestroy. Pointer у UIManager определяет наведение и нажатия; переопределяются OnMouseEnter/Exit, OnMousePressed/Released и OnMouseCancelled с MouseButton из Silk.NET.Input. Скрытие/удаление может отменить захваченное нажатие.

Пример в OnCreate собственного Canvas:

```csharp
var label = Add<ProjectShockGL.UI.Text>();
label.Rect.Position = new System.Numerics.Vector2(20, 20);
label.Rect.Size = new System.Numerics.Vector2(300, 60);
label.Font = ProjectShockGL.Content.LoadFont("NotoSans-Regular", 24);
label.Content = "Доступ разрешён / Access granted";
```

Text поддерживает растровый TTF-атлас, английский и русский текст, перенос строк, выравнивание и ClipToRect. Используйте шрифт с нужными глифами из Fonts; имя в примере предполагает Fonts/NotoSans-Regular.ttf. Font принадлежит кешу Content, отдельный Text его не освобождает. Следите за лицензией шрифта. UI обновляется на независимом времени.

### UIEvent и подписки из кода

UIEvent представляет событие без значения, UIEvent<T> — с одним типизированным значением. Оба поддерживают AddListener, RemoveListener, RemoveAllListeners и Invoke. Button предоставляет событие Click вместо прежних AddAction / RemoveAction / RemoveAllActions:

~~~csharp
button.Click.AddListener(OnClick);
button.Click.RemoveListener(OnClick);
button.Click.RemoveAllListeners();

var changed = new UIEvent<bool>();
changed.AddListener(OnChanged);
changed.Invoke(true);

void OnClick() { /* обработка клика */ }
void OnChanged(bool value) { /* обработка нового значения */ }
~~~

Обработчики вызываются в порядке добавления по снимку списка. Добавление, удаление или очистка во время вызова влияют на следующие вызовы; уже взятый снимок продолжает выполняться. RemoveListener снимает одно совпадающее вхождение; исключение обработчика передаётся вызывающему коду и останавливает текущий вызов. Необязательный Func<bool> в конструкторе проверяется перед каждым обработчиком и позволяет прекратить отправку события, когда его владелец недоступен.

Button.Click использует эту проверку: уничтожение, скрытие или отключение кнопки, её родителя или Canvas прекращает вызов оставшихся обработчиков. При уничтожении Button слушатели очищаются. Клик по-прежнему вызывается только при отпускании левой кнопки мыши над нажатой кнопкой. Подписки существуют только в памяти и не попадают в UI JSON; экземпляры UI-шаблона получают независимые события. Настроенные в UI Editor Actions выполняются после C#-слушателей и хранятся отдельно: RemoveAllListeners не удаляет Actions из ассета.

### Click Actions в UI Editor

Выделите Button и найдите Click / Actions в Inspector. Add action добавляет вызов; Remove удаляет его, Up и Down меняют порядок. Target выбирается из виджетов текущего экрана или Global actions. Method содержит только помеченные UIAction методы. Для метода без параметров дополнительное поле не показывается; один параметр редактируется как string, int, float или bool. Добавление, удаление, изменение цели, метода, параметра и порядка поддерживают Undo/Redo и сохраняются кнопкой Save в UI JSON.

Пример закрытия панели: Target — корневой виджет экрана, Method — Widget/Destroy(). Пример переключения видимости: Target — нужная панель, Method — Widget/Set visible(Boolean), Parameter — галочка. Для текста доступны Text/Set text(String), для всех виджетов — Set enabled и Set hit testing. В Global actions уже есть Level/Load(String) с именем уровня из Content/Levels без расширения и Application/Quit().

Общий метод игры объявляется в public-классе подключённой игровой сборки:

~~~csharp
using ProjectShockGL.UI;

public static class MenuActions
{
    [UIAction("Game/Show message")]
    public static void ShowMessage(string message)
    {
        ProjectShockGL.Log.Print(message);
    }
}
~~~

После пересборки игровой библиотеки и перезапуска редактора Game/Show message(String) появится в Global actions. Общие методы должны быть public static void; методы выбранного виджета — public void, включая унаследованные. Разрешены ноль параметров или один string/int/float/bool; generic, ref/out, несколько параметров и другие возвращаемые типы не предлагаются. Название в UIAction задаёт подпись в списке; реализация может обращаться к игровым системам обычным C#-кодом. Пользовательские типы виджетов по-прежнему не добавляются в Palette автоматически: UI JSON поддерживает прежние стандартные типы.

У виджетов появились внутренние Id. Ссылки Actions внутри ассета сохраняются по Id и разрешаются только среди виджетов созданного экземпляра: переименование, изменение порядка и создание нескольких экземпляров одного экрана не меняют адресата. Дублирование ветки выдаёт ей новые Id и переназначает ссылки на виджеты внутри копии; ссылки на цели вне ветки сохраняются. Удалённая цель показывается как Missing widget; Undo восстанавливает прежний Id. Старые UI-файлы без Actions продолжают загружаться, Id им назначаются автоматически. Сохранённый метод идентифицируется типом, сборкой, именем и сигнатурой; переименование C#-метода или класса требует повторного выбора метода в редакторе.

Сначала вызываются C#-слушатели Click, затем Actions по порядку. Actions не ждут окончания загрузки уровня или движения объекта. Если кнопка, экран или Canvas уничтожены, скрыты или отключены, оставшиеся Actions не запускаются. Ошибка метода, неверный параметр или отсутствующая цель записываются в Log и прерывают последовательность; уже выполненные вызовы не отменяются. RemoveAllListeners снимает только C#-подписки. Параметры Actions — константы; передача значения события и вызов Inputs объектов уровня через отдельный Target пока не добавлены.

В UI Editor Actions не исполняются, включая ручной Click.Invoke у предпросмотра. Для собственного предпросмотра используйте asset.Instantiate(canvas, enableActions: false). Обычная загрузка через Content.LoadUI(...).Instantiate(canvas) включает Actions автоматически.

## Ресурсы и настройки

### Структура Content

| Папка | Содержимое |
| --- | --- |
| Entities | JSON с Class и Parameters; поддерживаются вложенные папки |
| Geometry | JSON с Model, Texture, ColliderType, Size и другими параметрами |
| Details | JSON-описания декоративных мешей: Mesh, Texture, TextureFormat, Color, Lit, BackfaceCulling |
| Meshes | OBJ-модели |
| Textures | JPG/PNG |
| Fonts | TTF и лицензии |
| Shaders | GLSL .vert/.frag |
| PostProcessProfiles | JSON-профили эффектов |
| Levels | JSON-уровни с расширением .map |

Имена передаются относительно соответствующей папки, обычно без расширения: Entity.Create("Placeables/TimerEvent"), LevelManager.Load("MyLevel"), Content.LoadFont("NotoSans-Regular", 24). Текстуры используют отдельный TextureFormat. Для кешируемых ресурсов освобождение выполняет Content.UnloadAll; не удаляйте общий ресурс из одного объекта.

Уровень сохраняет размещения, трансформы, активность, Editable-свойства, Outputs, параметры brush, окружение, Groups и отдельный массив Details. Текущее выполнение корутин и таймеров не является сохранением игры и в map не записывается.

### GameSettings.ini, EditorSettings.ini и окно

```ini
[Window]
Mode=Windowed
Width=1280
Height=720
CanResize=true
VSync=true
Icon=Content/Textures/Game.png

[Rendering]
ResolutionScale=1.0
ResolutionFilter=Linear

[Application]
IsDebug=false

[Game]
Name=MyGame
Class=MyGame.MyGame, MyGame
UICanvasClass=MyGame.GameCanvas, MyGame
PostProcessingProfile=Default

[Content]
Path=Content
```

Window/VSync включает вертикальную синхронизацию (по умолчанию true). Для проверки производительности без синхронизации задайте VSync=false в GameSettings.ini и перезапустите игру. Параметр действует и в Windowed, и в Borderless; редактор читает его из собственного EditorSettings.ini.

Windowed использует Width/Height. Borderless использует размер основного монитора, скрывает рамку и не требует ручного разрешения. Это исходные настройки приложения; отдельной системы пользовательских настроек пока нет.

При Application/IsDebug=true игра показывает статистику в левом верхнем углу: FPS, интервал кадра, CPU-время Update и отправки рендера (не GPU-время), draw calls с разделением мира, постобработки и UI/Debug, число отправленных треугольников, разрешение мира и управляемую память .NET. Отрисовка самой статистики исключена из показанных счётчиков; blit не считается draw call. Оверлей обновляет текст четыре раза в секунду и использует Content/Fonts/NotoSans-Regular.ttf из стартовых ресурсов. В редакторе игровой оверлей не показывается. Заголовок окна содержит только название приложения.

Rendering/ResolutionScale задаёт разрешение мира от 0.1 до 1.0 (по умолчанию 1.0, значения за пределами ограничиваются). Например, 0.5 при окне 1920×1080 рисует мир в 960×540. ResolutionFilter=Linear сглаживает увеличение, Nearest сохраняет чёткие пиксели. Настройки читаются при запуске из GameSettings.ini или EditorSettings.ini. Масштабирование работает и без постобработки; UI, интерфейс редактора и его вспомогательная графика остаются в полном разрешении.

Icon — изображение для окна, путь относительно приложения. Иконка exe задаётся отдельно через ApplicationIcon в csproj и ICO-файл: изменение INI не пересобирает значок exe. В репозитории эти файлы уже настроены для игры и редактора.

Game/Class и UICanvasClass читает движок. StartupLevel, PlayerClass и PlayerCharacterClass читает архитектура ProjectOxygenGL: собственная игра не обязана использовать эти ключи. Layers.ini задаёт именованные слои; пример находится в [ProjectShockGLEditor/Layers.ini](ProjectShockGLEditor/Layers.ini).

## Проверки и ограничения

Примеры команд из корня:

```sh
dotnet run --project tests/LifecycleChecks
dotnet run --project tests/PhysicsChecks
dotnet run --project tests/EditorChecks -- --imgui
dotnet run --project tests/UIChecks
dotnet run --project tests/TextChecks
dotnet run --project tests/CoroutineChecks
dotnet run --project tests/InputChecks
dotnet run --project tests/MovementChecks
dotnet run --project tests/TimerChecks
dotnet run --project tests/PostProcessingChecks -- .
```

Проверки OpenGL требуют подходящего драйвера; PostProcessingChecks создаёт скрытое окно. EditorChecks с --imgui проверяет реальные события ImGui без видимого окна. После изменения API тестовые программы также могут требовать обновления; проверка актуальности примеров README не означает запуск всех тестов.

Текущие ограничения:

- Нет множественного выделения объектов, встроенного Play и сложного редактирования граней brush.
- Нет теней, запекания света и Bloom.
- Нет звуковой подсистемы, частиц и скелетной анимации.
- Нет полноценной динамики твёрдых тел и переноса на движущихся платформах.
- Нет отдельной системы материалов, твинов и сохранения состояния игрового сеанса.






### Общая поставка игры и редактора

Игра и отдельный запускатель редактора могут публиковаться рядом: ProjectA.exe, ProjectAEditor.exe, их DLL/deps/runtimeconfig, GameSettings.ini, EditorSettings.ini, Layers.ini, Icons и общий Content. Оба INI используют относительный Path=Content без CustomPath. Режим редактора задаётся вызовом Settings.Initialize(isEditor: true), а EditorSettings.ini выбирает редакторский Game/Class; GameSettings.ini выбирает Game игры. Разные имена настроек исключают перезапись конфигурации игры конфигурацией редактора.

Проект запуска редактора может ссылаться на игру для доступа к её Entity-классам. Игровой Game и редакторский Game запускаются раздельно. После изменения C# обновляйте комплект и перезапускайте приложения; изменение ресурсов на диске учитывает правила кеширования Content. Публикация с self-contained включает .NET, но все DLL и JSON запуска нужно хранить вместе с exe.

### Подключение редактора к следующей игре

В решении новой игры создайте отдельный исполняемый проект, например MyGame.Editor, со ссылками на MyGame.csproj и ProjectShockGLEditor.csproj. Файлы движка копировать не нужно. Добавьте существующие проекты движка в решение, если хотите редактировать их в Rider. ProjectOxygenGL уже является зависимостью редактора.

Точка входа MyGame.Editor:

```csharp
using ProjectShockGL;
using ProjectShockGLEditor;
using Game = ProjectShockGL.Core.Game;

Settings.Initialize(isEditor: true);
Game.Initialize();
Editor.Initialize();
Application.Run();
```

Добавьте EditorSettings.ini с копированием в вывод и публикацию. В нём задайте Game/Class=ProjectShockGLEditor.Game, ProjectShockGLEditor, Game/PostProcessingProfile=Default и Content/CustomPath к исходному Content новой игры. У игры остаётся отдельный GameSettings.ini. В редакторе создаются классы из той игры, на которую ссылается её запускатель.

Чтобы ресурсы сохраняли структуру при копировании между проектами, явно задавайте у Content метаданные:

```xml
<Content Include="Content\**\*.*">
    <Link>Content\%(RecursiveDir)%(Filename)%(Extension)</Link>
    <TargetPath>Content\%(RecursiveDir)%(Filename)%(Extension)</TargetPath>
    <CopyToOutputDirectory>Always</CopyToOutputDirectory>
    <CopyToPublishDirectory>PreserveNewest</CopyToPublishDirectory>
</Content>
```

Для разработки запускайте игру и её редактор из одного решения Rider с исходным Content. Для поставки используйте папку dist внутри проекта игры, общий вложенный Content и отдельные INI с пустым CustomPath. Публикуемые ресурсы — копии, поэтому правки из dist автоматически в исходники не возвращаются.


## UI-шаблоны в JSON

У Widget есть Name. Метод Find<T>(name) ищет первого потомка с указанным именем и типом, обходя дерево в глубину. Поиск доступен также у Canvas. Сравнение имён учитывает регистр; удалённые виджеты пропускаются. Корень не включается в поиск собственных потомков. Имена внутри панели выбирайте уникальными для однозначного поиска.

```csharp
var panel = canvas.Add<Widget>();
panel.Name = "Note";
var close = panel.Add<Button>();
close.Name = "Close";
close.Text.Content = "Закрыть";
Content.SaveUI("Screens/Note", panel);

var instance = Content.LoadUI("Screens/Note").Instantiate(canvas);
instance.Find<Button>("Close")!.Click.AddListener(instance.Destroy);

var nested = Content.LoadUI("Screens/Note").Instantiate(canvas, parentPanel);
```

JSON хранится в Content/UI/Screens/Note.json. Путь передаётся без расширения. SaveUI сохраняет переданный виджет и его потомков. Поддерживаются стандартные Widget, Image, Text, Button и TextScrollView. Встроенные части Button и TextScrollView восстанавливаются в уже созданные элементы.

Image поддерживает DrawMode = Simple (по умолчанию) и Sliced (9-slice). Border задаёт отступы в пикселях исходной текстуры или региона атласа в порядке Left, Top, Right, Bottom. BorderScale масштабирует рамку и повторяемые фрагменты. Углы сохраняют размер; EdgeMode и CenterMode независимо выбирают Stretch или Tile для полос и центра. FillCenter = false оставляет только рамку. Последняя плитка обрезается без растягивания; маленький Rect пропорционально уменьшает противоположные рамки. Настройки доступны в UI Editor и сохраняются в JSON. Слишком большое число плиток (более 16384 на часть) заменяется растягиванием этой части.

Пример настройки из кода:

~~~csharp
var panel = screen.Add<Image>();
panel.Region = Content.LoadTextureAtlas("Interface")!.GetRegion("Panel");
panel.Rect.Size = new Vector2(400, 200);
panel.DrawMode = ImageDrawMode.Sliced;
panel.Border = new Vector4(8, 8, 8, 8); // Left, Top, Right, Bottom
panel.BorderScale = 1;
panel.EdgeMode = ImageSliceMode.Tile;
panel.CenterMode = ImageSliceMode.Stretch;
panel.FillCenter = true;
~~~
Сохраняются Rect, имена, видимость, доступность ввода и настройки стандартных виджетов. Текстуры, шрифты и области атласа должны быть загружены через Content, чтобы при сохранении получить их имена. Файл содержит ссылки на эти ресурсы. Обработчики Click можно подключать игровым кодом; настроенные Click Actions сохраняются в UI JSON. Позиция прокрутки начинается сверху. Каждый вызов Instantiate создаёт собственное дерево, разделяя загруженные графические ресурсы через Content.

## Редактирование UI

Окно открывается через Edit → UI Editor. Слева находятся дерево и кнопки добавления стандартных виджетов. Новый виджет становится дочерним для выделенного. Встроенные Image и Text кнопки и Body у TextScrollView доступны в дереве для настройки.

В Inspector справа задаются Name, Position, Size, Anchor, Pivot, видимость и параметры выбранного типа. Имена ресурсов указываются относительно соответствующих папок Content без расширения. Для Image можно задать Texture либо Atlas и Region. Для Text задаются Font и размер растрового шрифта.

В центре показывается результат работы UI-рендерера. Preview size задаёт виртуальный размер Canvas. В предпросмотре можно выбрать виджет левой кнопкой мыши и переместить перетаскиванием. Выделенный элемент обведён рамкой. Esc отменяет текущее перемещение. Масштаб предпросмотра, Anchor и Pivot учитываются автоматически. Щелчок по встроенному тексту или фону кнопки выбирает кнопку; Body у TextScrollView выбирается вместе с прокручиваемым контейнером. Отдельные настройки внутренних элементов доступны в дереве. Предпросмотр масштабируется, чтобы помещаться в окно.

Save и Ctrl+S в активном UI Editor открывают файловый диалог сохранения. Open открывает файловый диалог выбора JSON. Диалоги начинают работу в Content/UI; экран сохраняется в этой папке или её подпапках. Отмена диалога сохраняет текущий документ и историю. Сохранение UI работает отдельно от сохранения уровня. В панели находятся New, Open, Save, Undo и Redo; имя экрана и отметка несохранённых изменений показаны в заголовке окна. New и Open запрашивают подтверждение, если есть несохранённые изменения. При закрытии приложения также появляется подтверждение. Закрытие самого окна сохраняет документ в памяти до завершения редактора.

Размеры можно менять ручками на углах и серединах сторон выделенного виджета. Противоположный край остаётся на месте. Esc восстанавливает размер и позицию до перетаскивания. Встроенные части Button и Body у TextScrollView получают размер от своего контейнера; изменяйте размер самого составного виджета. Другие свойства редактируются через Inspector. Кнопки Undo/Redo и Ctrl+Z / Ctrl+Y в активном UI Editor отменяют и повторяют перемещение, изменение размера и свойств, создание и удаление виджетов. Одно перетаскивание или непрерывное редактирование поля занимает один шаг. История UI независима от истории уровня, сохраняется после Save и очищается при New/Open. Ctrl+Z и Ctrl+Y управляют историей UI-документа также при редактировании его текстовых свойств. Сохранённый JSON загружается через Content.LoadUI(name).Instantiate(canvas).

Корень UI-ассета представляет экран. При Instantiate его Position, Anchor и Pivot равны нулю, а Size автоматически следует за Canvas, включая последующие изменения разрешения. В UI Editor размер корня задаётся через Preview size. Поля Rect корня заблокированы, ручки размера и перетаскивание для него отключены. Старые ассеты загружаются с этим же поведением. Панели и другие элементы размещаются дочерними виджетами.

Слева сверху находится Hierarchy, снизу — Widgets. Кнопки Widget, Image, Text, Button и TextScrollView создают дочерний элемент у текущего выделения.

FillCanvas у любого Widget заполняет весь Canvas, включая изменение разрешения. В UI Editor переключатель Fill Canvas блокирует поля Rect, перемещение и ручки размера. Исходный Rect сохраняется в JSON и восстанавливается при снятии флажка. Изменение флажка поддерживает историю UI. Корень экрана всегда заполняет Canvas.

Duplicate и Ctrl+D в активном UI Editor копируют выделенный виджет вместе с потомками рядом с оригиналом. Корень экрана и встроенные части составных виджетов отдельно не дублируются. Корень копии получает уникальное имя; имена внутри скопированного поддерева сохраняются. Действие отменяется одним шагом Undo/Redo.

В Hierarchy UI Editor виджеты можно перетаскивать. Сброс в верхнюю четверть строки ставит элемент перед ней, в нижнюю — после, в середину — делает дочерним. Порядок детей задаёт порядок рисования: поздние элементы рисуются поверх ранних. При смене родителя сохраняется экранная позиция с учётом Anchor и Pivot. FillCanvas продолжает заполнять Canvas. Один перенос отменяется одним шагом Undo/Redo. Корень и встроенные части Button/TextScrollView остаются закреплены, циклические связи запрещены.

Для отдельных иконок источников света положите PNG с прозрачным фоном в Content/Textures/Editor: PointLight.png, SpotLight.png и DirectionalLight.png. Иконка выбирается при загрузке и сразу обновляется при смене Type, включая Undo/Redo. Если нужного PNG нет, используется обычный DebugBillboard из ассета Light. Размер по-прежнему задаётся Debug/BillboardScale в EditorSettings.ini (для игры — GameSettings.ini). Сами изображения нужно подготовить отдельно.
