# ProjectShockGL

Небольшой игровой движок на C# и OpenGL с собственным редактором уровней. Разрабатывается для системной игры от первого лица, вдохновленной System Shock: комнаты, исследование, триггеры и связи между объектами.

Это личный инструмент для создания конкретной игры и изучения устройства движков. Проект не стремится быть универсальным: интерфейсы и возможности меняются по мере разработки игры. Если хочется разобраться, собрать свой уровень или попробовать добавить игровую механику — ниже описана текущая основа.

## Требования и запуск

- .NET SDK **8.0**. Настройки выбора SDK находятся в [global.json](global.json).
- Видеокарта и драйвер с поддержкой **OpenGL 3.3**.
- Разработка ведется на Windows; работа на других платформах не проверена.
- При первой сборке нужен доступ к NuGet для восстановления зависимостей.

Команды выполняются из корневой папки проекта:

```sh
dotnet build ProjectShockGL.sln
dotnet run --project ProjectShockGLEditor/ProjectShockGLEditor.csproj
```

Запуск игры отдельно:

```sh
dotnet run --project ProjectDungeon/ProjectDungeon.csproj
```

Также можно открыть решение в Rider или Visual Studio и выбрать стартовым проектом редактор либо игру. Встроенной кнопки Play в редакторе пока нет.

При сборке возможно предупреждение `NU1701` для используемой версии `ini-parser`: это известное предупреждение о целевой платформе пакета.

## Первый уровень

1. Запустите редактор. Создайте новую карту через **File → New** или откройте существующую через **File → Open**.
2. В **Palette → Geometry** выберите `Cube` и нажмите **Create**. Сейчас новый объект появляется в начале координат.
3. Измените Position, Rotation и Scale через **Inspector** или манипуляторы в сцене. Из кубов можно собрать пол, стены и препятствия.
4. В **Palette → Entity** создайте `PlayerStart` и разместите его в свободном месте над полом. Это позиция и поворот появления персонажа.
5. При необходимости добавьте источники света. Настройки окружения находятся в **View → Environment**.
6. Сохраните карту в **ProjectDungeon/Content/Levels**, например `MyLevel.map`.
7. В [ShockGame.cs](ProjectDungeon/Game/ShockGame.cs) измените имя в `LevelManager.Load("PolygonLevel")` на `"MyLevel"` — без расширения.
8. Запустите игровой проект. При изменении карты остановите игру и запустите ее снова.

В репозитории уже есть карты, которые можно открыть и использовать как примеры.

### BrushBox: стены и полы с повторяющейся текстурой

В Palette нажмите **Create BrushBox**. Это процедурный прямоугольный блок: для него не нужен OBJ-файл или отдельное JSON-описание Geometry.

В Inspector доступны:

- **Size** — полный локальный размер блока по X/Y/Z. Например, `(4, 3, 0.25)` задает стену шириной 4, высотой 3 и толщиной 0,25 при Scale = 1.
- **Texture** — общая текстура для шести граней из Content/Textures (JPG или PNG), либо WhitePixel для однотонного блока.
- **Texture scale** — количество повторений текстуры на мировую единицу. При значении 1 на стене шириной 4 текстура повторится четыре раза; при 2 — восемь раз.
- **Color**, **Lit**, **IsActive** и обычный Transform.

Коллайдер автоматически соответствует размеру блока. Масштабирование gizmo тоже меняет число повторений, сохраняя размер рисунка; вращение поворачивает текстуру вместе с блоком. BrushBox поддерживает сохранение в карту, дублирование и удаление. Изменение Size перетаскиванием поддерживает Undo/Redo. Редактирование граней, выдавливание и отдельные материалы для граней пока отсутствуют.

### Управление редактором

| Действие | Управление |
| --- | --- |
| Выбрать объект | ЛКМ в сцене или строка в списке Scene |
| Осмотреться | Удерживать ПКМ и двигать мышью |
| Перемещение камеры | ПКМ + WASD, Q/E — вниз/вверх |
| Сдвиг камеры | Удерживать среднюю кнопку мыши и двигать мышью |
| Фокус на выбранном объекте | F |
| Перемещение / вращение / масштаб | G / R / T или кнопки верхней панели |
| Изменить трансформ | Перетащить соответствующую ось или кольцо манипулятора |
| Привязка к шагу | Snap в панели или Shift при перетаскивании |
| Отмена текущего перетаскивания | Esc |
| Дублирование | Ctrl+D или Duplicate |
| Удаление | Delete или Delete в Inspector |
| Отмена / повтор редактирования | Ctrl+Z / Ctrl+Y |
| Новая карта / открыть | Ctrl+N / Ctrl+O |
| Сохранить / сохранить как | Ctrl+S / Ctrl+Shift+S |

Горячие клавиши сцены работают, когда редактор не занят вводом в поле. В общей истории сохраняются трансформы, значения Inspector (имя, IsActive, свойства сущностей и света, параметры BrushBox, редактирование/добавление/удаление Outputs) и изменения Environment, включая Reset. Одно перетаскивание числа/ползунка и один сеанс ввода текста дают один шаг; при переключении поля или объекта изменения завершаются. Ctrl+Z отменяет последнее действие независимо от его типа, Ctrl+Y повторяет его. В активном текстовом поле сохраняется собственная отмена ImGui. Создание через Palette, удаление и дублирование также входят в общую историю. Undo удаления восстанавливает объект с его именем, свойствами, Outputs и местом в списке сцены; предыдущие правки Inspector и gizmo продолжают работать с восстановленным экземпляром. Undo создания/дублирования удаляет объект и возвращает прежнее выделение. Redo восстанавливает тот же снимок, а не создает новую копию с новым именем. История очищается при открытии или создании уровня.

### Предпросмотр и окружение

В верхней панели есть независимые настройки просмотра:

- **Lit** — обычный рендер с учетом настройки освещения материала.
- **Unlit** — отображение сцены без влияния освещения.
- **Environment** — показ тумана и Ambient уровня. При отключении туман убирается, а Ambient предпросмотра становится белым.

Эти переключатели не изменяют карту, не влияют на игровой рендер и не помечают уровень как измененный. Параметры самого уровня редактируются отдельно в окне Environment и сохраняются в `.map`.

## Объекты и жизненный цикл

Основные классы:

- `Application` создает окно и графический контекст, вызывает события игрового цикла.
- `Game` содержит `World` и `UIManager`. Игровой класс выбирается через Settings.ini.
- `World` владеет объектами: создает, обновляет, отрисовывает и уничтожает их.
- `ProjectShockGL.Core.Object` содержит Transform, компоненты, слой и состояние активности.
- `Entity` добавляет описание ресурса, редактируемые свойства и Outputs для игровой логики.
- `Geometry` представляет размещаемую геометрию с визуальной частью и коллайдером. Она помечается статической.

Для создания объектов используйте `World.Spawn<T>()`, `Entity.Create(...)` или `Geometry.Create(...)`, а для удаления — `World.Destroy(obj)`. `World.Clear()` освобождает весь мир, включая объекты, ожидающие первого обновления.

Порядок работы:

1. При создании сразу вызывается `Create()`.
2. Объект ожидает регистрации в первом `World.Update`. К этому моменту загрузчик назначает свойства и трансформ из карты.
3. Для активного объекта вызывается начальный `OnActiveChanged(true)`, затем `Start()`.
4. `Start()` вызывается один раз. Для изначально выключенного объекта он откладывается до первого активного обновления.
5. Активные нестатические объекты получают `Update(deltaTime)`. Повторное включение не повторяет Start.
6. При уничтожении освобождаются компоненты. Уничтоженный объект нельзя включить снова.

В переопределениях жизненного цикла вызывайте базовый метод, если нужно сохранить обработку компонентов.

`SetActive(false)` отключает обновление, отрисовку и участие в физических запросах. Выключенный Light перестает освещать сцену. Объект при этом остается доступен через `World.Find(...)`.

`World.Find<T>()` и `World.Find(name)` учитывают созданные объекты, еще ожидающие Start. Наличие объекта в поиске не означает, что его Start уже выполнен.

### Загрузка уровня

`LevelManager.Load("MyLevel")` загружает карту из `Content/Levels/MyLevel.map`. Также можно передать экземпляр `Level`.

Есть события `Loading`, `Loaded`, `Unloading`, `Unloaded`, свойства `ActiveLevel`, `IsLoading` и метод `Unload()`.

В `Loaded` новый мир и Environment уже назначены, но объекты еще не получили Start. В этом обработчике удобно найти PlayerStart и создать персонажа. Пример подписки и отписки есть в [ShockGame.cs](ProjectDungeon/Game/ShockGame.cs).

Загрузка синхронная. Новый уровень сначала подготавливается отдельно: ошибка создания его объектов не удаляет старую сцену. Вложенная загрузка из обработчика перехода запрещена. При замене карты Unloaded относится к уже удаленному старому уровню; новый мир в этот момент уже установлен.

## Игровая логика и связи объектов

В Inspector у сущностей есть **Name**, редактируемые свойства и список **Outputs**. Связь содержит:

| Поле | Значение |
| --- | --- |
| Event | Имя события, которое обрабатывает код сущности |
| Target | Точное имя целевого объекта в мире |
| Input | Метод цели, помеченный атрибутом `[Input("...")]` |
| Parameter | Аргумент или аргументы метода, разделенные запятыми |

Outputs сами по себе не вызываются: код сущности решает, когда отправлять событие. Пример реализации находится в [Trigger.cs](ProjectDungeon/Core/Trigger.cs). Этот триггер реагирует на вход `PlayerCharacter` и обрабатывает Outputs с Event `OnTriggerEnter`.

### Включить объект через триггер

1. Дайте целевому объекту уникальное имя, например `room_light`.
2. Снимите у него **IsActive** в Inspector. Это состояние сохранится в карту. Выключенные объекты можно выбрать через список Scene, где они отмечены `(inactive)`.
3. Создайте Trigger, разместите и масштабируйте его область.
4. Добавьте ему Output: Event = `OnTriggerEnter`, Target = `room_light`, Input = `SetActive`, Parameter = `true`.
5. Сохраните карту и проверьте ее в игре.

Для выключения используйте `false`. Для bool-параметров нужны именно `true`/`false`, а не `1`/`0`. Числа в параметрах записываются с точкой в качестве десятичного разделителя. Имена целей лучше делать уникальными: поиск возвращает первый подходящий объект.

### Добавить свою сущность

Создайте класс в игровом проекте, унаследованный от `Entity`. Атрибут `[Editable]` открывает свойства в Inspector, `[Input]` позволяет вызывать метод через Outputs.

Например, файл `ProjectDungeon/Core/Door.cs`:

```csharp
using System.Numerics;
using ProjectShockGL.Core;

namespace ProjectDungeon.Core;

public class Door : Entity
{
    private bool _opened;

    [Editable]
    public Vector3 OpenOffset { get; set; } = new(0, 2, 0);

    public override void Create()
    {
        base.Create();
        AddComponent<BoxCollider>();
    }

    [Input("Open")]
    public void Open()
    {
        if (_opened) return;
        _opened = true;
        Transform.Position += OpenOffset;
    }
}
```

Создайте `ProjectDungeon/Content/Entities/Door.json`:

```json
{
  "Class": "ProjectDungeon.Core.Door, ProjectDungeon",
  "Parameters": {}
}
```

После пересборки и перезапуска редактора Door появится в Palette → Entity. Это пример логики и коллайдера: визуальную модель двери нужно добавить отдельно, например через MeshComponent в Create. В Parameters можно передавать настройки ресурса, которые сущность читает в `Load(...)`; пример — DebugBillboard у Trigger.

## Ресурсы и настройки

Ресурсы загружаются через `Content` по именам относительно соответствующих папок:

| Папка в Content | Содержимое |
| --- | --- |
| Entities | JSON-описания классов сущностей и их параметров |
| Geometry | JSON-описания геометрии: модель, текстура, цвет, коллайдер, Lit |
| Meshes | Модели `.obj` |
| Textures | Текстуры `.jpg` и `.png` |
| Fonts | Шрифты `.ttf` и их лицензии |
| Shaders | Шейдеры `.vert` и `.frag` |
| Levels | Уровни `.map` в формате JSON |

Имя обычно передается без расширения: `Content.LoadMesh("Cube")`, `Entity.Create("Trigger")`, `Content.LoadFont("NotoSans-Regular", 24)`.

`Content.LoadTexture("Name")` по умолчанию ищет JPG. Для PNG используйте `Content.LoadTexture("Name", TextureFormat.Png)`. В описании Geometry значение Texture `WhitePixel` означает встроенную белую текстуру. У BoxCollider свойство HalfExtents, а также поле Size в текущем описании Geometry задают **полуразмеры** коллайдера.

После добавления новых ресурсов перезапустите редактор: списки Palette и загруженные ресурсы кэшируются.

У игры и редактора собственные Settings.ini. В секции Game задаются Class и, при необходимости, UICanvasClass в формате `Полное.Имя.Класса, ИмяСборки`. В Content.Path задается папка ресурсов относительно исполняемого файла. Content.CustomPath переопределяет ее; относительное значение тоже считается от папки исполняемого файла.

Редактор по умолчанию читает исходную папку `ProjectDungeon/Content` через CustomPath. Игра использует копию Content, которую сборка помещает рядом с исполняемым файлом. Поэтому сохраняйте карты в исходную папку и запускайте игру с пересборкой. При изменении структуры выходных папок проверьте CustomPath редактора.

Слои описаны в Layers.ini. `Layers.Get("Player")` возвращает маску слоя, `CollidesWith` задает маску взаимодействий. В игровой конфигурации уже есть Default, Player и Trigger.

### Режим окна

В Settings.ini игры и редактора можно независимо задать режим:

```ini
[Window]
Mode=Windowed
Width=1280
Height=720
CanResize=true
```

- **Windowed** — обычное окно. Width и Height задают размер клиентской области, CanResize разрешает изменение размера.
- **Borderless** — окно без рамки на весь основной монитор. Размер берется из текущего разрешения монитора; Width, Height и CanResize игнорируются. Это не эксклюзивный Fullscreen: видеорежим монитора не переключается.

Для Borderless достаточно заменить строку на `Mode=Borderless`. Если Mode отсутствует или пуст, используется Windowed. Регистр букв не важен. Изменения применяются при следующем запуске; пользовательские настройки отдельно не сохраняются. По умолчанию оба проекта остаются в Windowed.

### Иконка окна

Параметр `Icon` в секции `[Window]` файла Settings.ini задает PNG-иконку окна:

```ini
[Window]
Icon=Icons/Editor.png
```

Относительный путь считается от папки исполняемого файла, независимо от Content.CustomPath; можно указать и абсолютный путь. Пустой или отсутствующий Icon оставляет стандартную иконку. Если файл не удалось прочитать, причина выводится в консоль, а запуск продолжается.

У игры настроен `Content/Textures/Icon.png`, у редактора — отдельный файл `Icons/Editor.png`. Их можно заменить независимо. Иконка редактора автоматически копируется из ProjectShockGLEditor/Icons, игровая — вместе с Content.

Иконки самих EXE в проводнике встроены через ApplicationIcon в соответствующих csproj:

- `ProjectDungeon/Icons/Game.ico` — создана из игровой PNG-иконки.
- `ProjectShockGLEditor/Icons/Editor.ico` — создана из PNG-иконки редактора.

ICO содержит варианты от 16×16 до 256×256. При замене изображения нужно обновить соответствующие PNG и ICO, затем пересобрать проект: Settings.ini меняет только иконку окна, а иконка EXE назначается при сборке.

## Освещение и Spotlight

Создайте сущность Light в Palette и выберите в Inspector Type: Directional, Point или Spot. У Spot используются общие Color, Intensity и Radius, а направление задается поворотом объекта — вдоль Transform.Forward (локальная ось −Z).

У Spotlight есть два дополнительных параметра:

- **Inner angle** — полная ширина конуса в градусах, внутри которой свет имеет полную угловую интенсивность.
- **Outer angle** — полная ширина внешнего конуса. Между двумя границами свет плавно затухает, за внешней границей отсутствует.

По умолчанию углы равны 30° и 45°. При увеличении внутреннего угла за внешнюю границу внешний расширяется; при уменьшении внешнего внутренний сужается. При равных углах край жесткий. Радиус задает предельное расстояние от источника, затухание по расстоянию сохраняется.

Для выбранного Spot редактор рисует внешний конус желтым, внутренний голубым и ось белым. Контуры помогают направлять свет обычным манипулятором вращения. Тип, углы и остальные Editable-параметры сохраняются в карте и копируются при дублировании.

Point и Spot используют общий лимит 16 активных локальных источников. Выключенный Light не занимает место в этом лимите. Для проверки освещения выберите Lit в предпросмотре и материал с Lit=true; слишком яркий Ambient может скрывать рисунок света. Тени и фонарик игрока пока отсутствуют.

## Коллизии и персонаж

Доступны BoxCollider, SphereCollider и CapsuleCollider, события входа/выхода столкновений и триггеров, Raycast, OverlapSphere, OverlapSphereAll и OverlapCapsule.

В запрос можно передать фильтр, чтобы исключить владельца и триггеры:

```csharp
var filter = new PhysicsQueryFilter
{
    IgnoreObject = this,
    IgnoreTriggers = true
};

if (Physics.Raycast(Transform.Position, Transform.Forward, 2f,
        Layers.Everything, out var hit, filter))
{
    Console.WriteLine(hit.Object.Name);
}
```

CharacterController наследует CapsuleCollider. `Move(displacement)` принимает **смещение в мировых координатах**, а не скорость. Если задана скорость, умножайте ее на deltaTime. Гравитация задается игровым кодом. Есть IsGrounded, GroundNormal, CollisionFlags, StepOffset и SlopeLimit. По умолчанию высота ступеньки — 0,3 мировой единицы, допустимый уклон — 45°.

Текущая физика предназначена для простого кинематического движения и запросов. Здесь нет полноценной динамики твердых тел, сил, автоматического выталкивания из начального пересечения или автоматического скольжения вниз по крутому склону.

В игровом проекте [Player](ProjectDungeon/Game/Player.cs) читает ввод, а [PlayerCharacter](ProjectDungeon/Game/PlayerCharacter.cs) управляет движением и взглядом персонажа. Управление примером: WASD и мышь, Esc — выход.

## UI

Game создает sealed UIManager, а тот — один Canvas, класс которого задан в Settings.ini. HUD, панели и другие экраны размещаются внутри этого Canvas как виджеты. Widget поддерживает детей и родителя; Parent == null означает корень Canvas.

RectTransform использует начало координат в левом верхнем углу: X направлен вправо, Y — вниз. Доступны Position, Size, Anchor и Pivot. Это пока простая система без растяжения по двум якорям и вращения UI.

Пример кода внутри `Canvas.OnCreate()`:

```csharp
var label = Add<ProjectShockGL.UI.Text>();
label.Rect.Position = new System.Numerics.Vector2(24, 24);
label.Rect.Size = new System.Numerics.Vector2(400, 80);
label.Font = ProjectShockGL.Content.LoadFont("NotoSans-Regular", 24);
label.Content = "Доступ разрешен\nAccess granted";
label.Color = ProjectShockGL.Rendering.Color.Green;
```

Text использует растровый атлас TTF, поддерживает русский и английский текст, переносы, выравнивание и обрезку по собственному Rect. Размер шрифта задается при загрузке; для другого размера загрузите тот же шрифт с другим числом пикселей. Шрифт общий: виджет не должен освобождать его при удалении. Noto Sans включен вместе с [лицензией OFL](ProjectDungeon/Content/Fonts/OFL.txt).

Для интерактивности переопределяйте у Widget методы OnMouseEnter, OnMouseExit, OnMousePressed, OnMouseReleased и OnMouseCancelled. UIManager.Pointer выбирает верхний виджет и удерживает получателя нажатия до отпускания. Text по умолчанию пропускает указатель; у декоративных виджетов можно отключать HitTestVisible.

Указатель UI работает при обычном видимом курсоре и активном окне. Для открытия игрового меню переключайте CursorMode.Raw на CursorMode.Normal; при возврате в игру — обратно. UI пока не блокирует игровой ввод автоматически.

## Текущие границы проекта

- Освещение без динамических теней и без запекания.
- Редактор собирает уровни из подготовленных ресурсов; полноценного браузера импорта, редактора материалов и Play Mode пока нет.
- Сохранение уровня описывает размещенные объекты и Environment, а не произвольное состояние всех runtime-компонентов. Это не система сохранений прохождения.
- Активность объектов сохраняется в карте, но отдельные флаги компонентов не являются универсально сериализуемыми настройками.
- API и формат ресурсов могут меняться вместе с игрой. Рабочие примеры в ProjectDungeon и код соответствующих систем служат ориентиром при расширении.

### Выполнение объектов в редакторе

В редакторе вызывается Create для создания компонентов и ресурсов, но не вызываются игровой Start, Update и начальный OnActiveChanged. Физические запросы остаются доступны для инструментов, обработка столкновений и триггеров не выполняется. Игровую логику начала уровня размещайте в Start; Create должен подготавливать объект и его представление в редакторе. Start по-прежнему вызывается один раз при первом включении объекта в игре. Собственного Play Mode в редакторе пока нет.

При ошибке создания компонент освобождается и удаляется из владельца. Очистка объектов и ресурсов продолжается при ошибках отдельных обработчиков, после чего ошибки возвращаются как AggregateException. Переопределяя Destroy, освобождайте свои ресурсы через try/finally и вызывайте base.Destroy().

### Шейдер отдельного объекта

У MeshComponent, QuadComponent, BillboardComponent и LineRenderer есть Shader и собственный ShaderParameters. Если Shader не задан, работает прежний Lit / Unlit. Программа загружается и кэшируется Content по паре имен файлов из Content/Shaders; расширения указывать не нужно:

```csharp
var mesh = AddComponent<MeshComponent>();
mesh.Mesh = Content.LoadMesh("Cube");
mesh.Texture = Content.GetWhitePixel();
mesh.Shader = Content.LoadShaderProgram("Deform", "Unlit");
mesh.ShaderParameters.Set("uAmplitude", 0.2f);
mesh.ShaderParameters.Set("uSpeed", 2f);
mesh.ShaderParameters.Set("uFrequency", 3f);
```

Здесь используются Deform.vert и существующий Unlit.frag. Для освещенной версии можно выбрать пару `("Deform", "Lit")`. Одна программа может использоваться многими объектами; параметры принадлежат каждому компоненту отдельно. Менять их можно в любое время, например из Update. В очередь отрисовки попадает снимок параметров. Remove и Clear возвращают отсутствующие значения к исходным значениям GLSL, не оставляя параметры предыдущего объекта.

Set поддерживает float, int, bool, Vector2/3/4, Color (как vec4) и Matrix4x4. Тип должен совпадать с uniform в GLSL. Массивы и дополнительные текстуры пока не поддерживаются. Отсутствующие или оптимизированные компилятором uniform игнорируются. Служебные параметры нельзя задавать через ShaderParameters.

Renderer автоматически передает `uModel`, `uView`, `uProjection`, `uTexture` (текстура компонента на слоте 0), `uColor`, `uUvRect`, `uAlphaCutoff`, `uTime` (секунды с создания Renderer, включая предпросмотр), `uCameraPos`, параметры тумана и существующего освещения. Пользовательский шейдер может объявлять только нужные ему uniform. Раскладка вершин прежняя: location 0 — vec3 position, 1 — vec3 normal, 2 — vec2 UV. Матрицы передаются так же, как во встроенных шейдерах.

Назначенная программа определяет освещение самостоятельно: флаг Lit выбирает встроенный шейдер только при Shader == null. Режим Unlit редактора передается как bool `uForceUnlit`: стандартный Lit.frag его учитывает, собственный фрагментный шейдер должен обработать его сам. Environment управляет передаваемыми туманом и ambient, но не может автоматически изменить произвольный GLSL. Проход UI продолжает использовать встроенный Unlit.

Для проверки после пересборки и перезапуска редактора выберите Palette → Entity → DeformationExample. Это голубой куб с вершинной деформацией по X; Amplitude, Speed и Frequency доступны в Inspector, сохраняются в карту и копируются обычным механизмом Editable-свойств. Amplitude = 0 отключает деформацию, Speed = 0 останавливает волну. У куба мало вершин, поэтому изгиб угловатый; для плавной волны нужна более подробная сетка. Эффект меняет только изображение: коллайдер и границы выбора остаются исходными.

Программы и исходные шейдеры принадлежат Content и освобождаются при UnloadAll; уничтожение объекта не удаляет общую программу. Изменения GLSL требуют перезапуска. Назначение программы произвольному компоненту выполняется в коде; универсального редактора параметров шейдеров и отдельного формата материалов пока нет.
### Постобработка мира

Мир рисуется в отдельную цветовую текстуру с буфером глубины, затем PostProcess.vert и PostProcess.frag выводят ее в окно. После этого рисуются debug-компоненты, сетка и выделение редактора (RenderOverlay), игровой UI (RenderUI) и ImGui (AfterRender). Виньетка не обрабатывает эти слои. Глубина мира переносится в окно, поэтому сетка продолжает скрываться за геометрией.

PostProcessSettings — статичный класс текущего состояния. Значения эффекта хранятся в JSON-профилях Content/PostProcessProfiles, а не в Settings.ini. В комплекте есть Default.json:

```json
{
  "Enabled": true,
  "VertexShader": "PostProcess",
  "FragmentShader": "PostProcess",
  "Parameters": {
    "uVignetteStrength": 0.45,
    "uVignetteRadius": 0.3,
    "uVignetteSoftness": 0.5,
    "uGrainStrength": 0.0,
    "uGrainSize": 1.0,
    "uChromaticAberrationPixels": 0.0
  }
}
```

Strength — сила затемнения от 0 до 1; Radius — радиус незатемненной области (0 — центр, 1 — углы экрана); Softness — ширина плавного перехода. Значения заданы в нормализованных координатах экрана. Это отдельный ресурс, в файл уровня он не записывается. Игра и редактор применяют Default в своих Load; другой профиль можно выбрать там же. В редакторе View → Post processing переключает эффект только для текущего предпросмотра.

```csharp
PostProcessSettings.Apply("Default");

// При необходимости загрузку и применение можно разделить:
var profile = Content.LoadPostProcessProfile("Default")
    ?? throw new FileNotFoundException("Missing postprocess profile: Default");
PostProcessSettings.Apply(profile);

// Временные изменения не изменяют профиль в кэше Content.
PostProcessSettings.Parameters.Set("uVignetteStrength", 0.6f);
PostProcessSettings.Enabled = false;
```

Content.LoadPostProcessProfile принимает имя без расширения, возвращает null для отсутствующего файла и кэширует описание без создания GPU-программы. Apply("имя") сообщает об отсутствии файла исключением. При применении загружается программа, параметры преобразуются по реальным типам uniform в GLSL, затем целиком заменяется текущее состояние. Ошибка шейдера или значения не меняет прежний эффект. Неуказанные параметры предыдущего профиля удаляются, uniform возвращаются к исходным значениям GLSL. Словарь/JToken профиля и текущие параметры не разделяют изменяемые значения. Все изменения времени выполнения остаются в памяти; файл JSON не переписывается.

Enabled по умолчанию true, VertexShader — PostProcess, FragmentShader — PostProcess, Parameters — пустой словарь. Поэтому профиль виньетки можно сократить до объекта с Parameters. Строки с именами шейдеров задаются без расширения. Пример нового эффекта: FragmentShader = "MyPostEffect", VertexShader = "PostProcess".

PostProcess.frag объединяет хроматическую аберрацию, виньетку и film grain в одном проходе. В Default сила зерна и аберрации равна нулю; виньетка сохраняет прежние значения. Дополнительные параметры профиля:

- `uGrainStrength` — сила монохромного зерна от 0 до 1, по умолчанию 0. Шум прибавляется к RGB после виньетки и обновляется 24 раза в секунду; альфа не меняется.
- `uGrainSize` — размер зерна в физических пикселях framebuffer, по умолчанию 1. Значения меньше 1 обрабатываются как 1.
- `uChromaticAberrationPixels` — максимальное смещение красного и синего каналов в противоположные стороны, в пикселях, по умолчанию 0. Эффект усиливается от центра к углам, где каждый канал смещается на заданное расстояние; зеленый канал и альфа берутся из исходной координаты. Отрицательная сила отключает эффект.

Например, в Parameters своего JSON-профиля можно задать `"uGrainStrength": 0.03`, `"uGrainSize": 1.0`, `"uChromaticAberrationPixels": 1.5`. При нулевой силе дополнительные эффекты не меняют изображение. UI и инструменты редактора остаются вне постобработки. Bloom пока не реализован.

Правила значений в Parameters:

- float: JSON-число, включая целое `1`; бесконечности, NaN и переполнение float отклоняются.
- int: целое в диапазоне Int32; запись `2.0` допустима, `2.5` и переполнение отклоняются.
- bool: true/false или числа 0/1.
- vec2/3/4: массив ровно из 2/3/4 чисел. Также поддерживаются объекты X/Y/Z/W или R/G/B/A без учета регистра. Для vec4 цвет записывается как `[r,g,b,a]`.
- mat4: 16 чисел по строкам, четыре массива-строки по четыре числа или объект M11..M44. Из кода можно передавать Matrix4x4, векторы и Color.

Массивы uniform, дополнительные текстуры и другие типы пока не поддерживаются. Как у ShaderParameters, отсутствующие/оптимизированные uniform игнорируются. Служебные имена (`uTexture`, `uTime`, матрицы камеры и другие параметры Renderer) зарезервированы. Ошибки загрузки указывают файл, ошибки преобразования — имя параметра и тип uniform.

MyPostEffect.frag получает `in vec2 vTexCoord`, текстуру мира `uniform sampler2D uTexture`, время `float uTime`, размер кадра `vec2 uScreenSize` и размер текселя `vec2 uTexelSize`. Начните с `vec4 scene = texture(uTexture, vTexCoord);`, измените scene.rgb и запишите результат в `out vec4 FragColor`. Это один проход, цепочки эффектов пока нет. Shader = null возвращает встроенную виньетку. Reset выключает эффект, сбрасывает Shader и очищает параметры. Content.UnloadAll вызывает Reset и очищает кэш профилей. Изменения JSON на диске требуют перезапуска или выгрузки Content, как и остальные кэшируемые ресурсы.

При собственной ручной отрисовке через Graphics последовательность такая: BeginDraw → BeginWorld → отрисовка мира → EndWorld → отрисовка интерфейса → EndDraw. Application выполняет это автоматически; EndWorld вызывайте в finally. Программа и параметры фиксируются в BeginWorld: профиль, примененный во время рисования мира, вступит в действие целиком в следующем кадре. Все Renderer используют статичный PostProcessSettings; до применения профиля постобработка выключена. Буферы пересоздаются при изменении размера framebuffer и освобождаются вместе с Renderer.

### Пример своего фрагментного шейдера объекта

В Content/Shaders/Pulse.frag есть небольшой пример пульсации цвета с текстурой, прозрачностью и поддержкой тумана. Его можно использовать без собственного вершинного шейдера:

```csharp
mesh.Shader = Content.LoadShaderProgram("Unlit", "Pulse");
mesh.ShaderParameters.Set("uPulseColor", new Vector3(0.2f, 0.8f, 1f));
mesh.ShaderParameters.Set("uPulseSpeed", 2f);
mesh.ShaderParameters.Set("uPulseStrength", 0.5f);
```

Чтобы совместить пульсацию с деформацией, выберите пару `("Deform", "Pulse")`. Оба вершинных шейдера передают нужные Pulse.frag значения vTexCoord и vWorldPos. Pulse не рассчитывает освещение: он окрашивает текстуру и применяет туман. Для другого эффекта можно скопировать этот файл, изменить вычисление цвета в main и загрузить новую пару имен.

Проверки постобработки в скрытом окне OpenGL: `dotnet run --project tests/PostProcessingChecks -- .`. Они проверяют виньетку, независимость UI/overlay, перенос глубины, восстановление GL-состояния, изменение размера, освобождение ресурсов, порядок событий Application и пример Pulse.
Проверка реальных событий ImGui для Inspector и Environment без открытия окна: `dotnet run --project tests/EditorChecks -- --imgui`. Она проверяет клики, много кадров перетаскивания числа и набор текста как единый шаг истории.

Операции с объектами в инструментах редактора выполняются через `SceneObjects.Create(type, path)`, `SceneObjects.Duplicate(source)` и `SceneObjects.Delete(obj)`: они регистрируют действия истории и обновляют dirty state. Низкоуровневый `EditorLevelManager.DuplicateObject` по-прежнему только создает копию. Восстановление создает новый экземпляр через обычный Create; сам уничтоженный объект не оживает. Редакторские действия используют EditorObjectReference для связи с актуальным экземпляром. Start и игровая логика при восстановлении в редакторе не запускаются. Снимки хранятся в памяти, отдельные идентификаторы истории в файл уровня не записываются.
### Время и таймеры

`Application.TimeScale` (по умолчанию `1`) задаёт скорость игрового времени: `0` — пауза, `0.5f` — половинная скорость. Отрицательные и нечисловые значения запрещены. `Application.Time` и `DeltaTime` — игровое время, `UnscaledTime` и `UnscaledDeltaTime` — независимое время. Событие `Application.Update` сохраняет реальный шаг кадра; базовый `Game` масштабирует шаг для `World`, обновляет таймеры обоими шагами, а UI оставляет на независимом времени. Объекты продолжают получать Update с нулевым шагом при паузе: произвольная логика и ввод сами по себе не блокируются. Физические запросы доступны, автоматическая обработка пересечений при нулевом шаге приостановлена.

`new ProjectShockGL.Core.Timer()` использует игровое время, `new ProjectShockGL.Core.Timer(useUnscaledTime: true)` — независимое. `Run(seconds)` запускает или перезапускает отсчёт; `SetPaused` приостанавливает его, `IsRunning()` остаётся true во время паузы, `IsPaused` сообщает о паузе. `RemainingSeconds` хранит остаток. `Stop()` отменяет без Finished, `Complete()` принудительно завершает работающий таймер. При завершении остаток равен нулю, сначала приходит `ValueChanged(0)`, затем `Finished`. Отмена или перезапуск из ValueChanged отменяет устаревшее уведомление Finished. `Dispose()` освобождает таймер, повторный запуск после него запрещён. Владелец обязан вызывать Dispose при уничтожении.

У `TimerEvent` настройка `UseUnscaledTime` читается при каждом Run; доступны Inputs Run, SetRemaining, SetPaused, Stop, Complete и Output OnFinished. Старый TimerType/OneSecond удалён: существующие таймеры уровня по умолчанию используют игровое время. Корутины эта система не добавляет.

### Значение события в Outputs

`Entity.InvokeEvent("OnValueChanged", value)` передаёт одно динамическое значение связанным Inputs. Совместимый Input с одним аргументом получает значение события вместо поля Parameter. Поддерживаются совпадающие типы, числовые преобразования и преобразование в строку с независимым от языка форматированием. Число не преобразуется автоматически в bool. Если значение несовместимо или у Input несколько аргументов, используется обычный Parameter из Output. Input без аргументов вызывается без параметров. Вызов `InvokeEvent("OnFinished")` сохраняет прежнее поведение.

`TimerEvent` публикует `OnValueChanged` с остатком времени: при Run, изменении остатка, отсчёте и завершении (значение 0). В Inspector у Output укажи Event = OnValueChanged, Target и нужный Input; Parameter служит резервным значением при несовместимой сигнатуре. Формат файла уровня не изменяется.

### Вытеснение CharacterController

При `Physics.Update()` после перемещения объектов капсула CharacterController автоматически вытесняется из твёрдых коллайдеров, даже если персонаж не вызывал Move. Поддерживаются BoxCollider (включая поворот), SphereCollider и CapsuleCollider. Учитываются CollisionMask, CollidesWith обеих сторон, активность и включение компонентов; собственные коллайдеры и триггеры исключаются. В редакторе вытеснение отключено. Используется уменьшенный на SkinWidth радиус, как при Move; после коррекции обновляется состояние опоры. LastDisplacement сохраняет результат последнего явного Move.

Количество проходов ограничено: это простое устранение пересечения, без масс, сил, переноса на платформе и обработки зажатия. Быстрый объект, полностью прошедший сквозь персонажа за один кадр, не обнаруживается этим способом. Вызов Physics.Update при TimeScale = 0 базовый Game пропускает.

### Папки ресурсов и поиск

Palette отображает вложенные папки Content/Entities и Content/Geometry как раскрывающиеся категории. Search assets ищет по имени и полному относительному пути без учёта регистра, раскрывая совпавшие категории. Выбери ресурс и нажми Create. Refresh перечитывает список после добавления файлов. В уровне сохраняется относительный путь ресурса; одинаковые имена в разных папках не конфликтуют. Перенос уже используемого ресурса в другую папку требует обновления ссылок в уровнях.

В Inspector у BrushBox список Texture также показывает папки Content/Textures и поиск по пути. Поддерживаются PNG/JPG и WhitePixel; выбор текстуры сохраняет Undo/Redo. Новые файлы появляются при следующем отображении списка.

### Groups в редакторе

В окне Scene раскрой Groups, введи имя и нажми Create group. Выдели объект в сцене или списке, раскрой группу и нажми Add selected. Remove исключает объект из группы; Delete group удаляет только группу, сохраняя объекты. Переключатель возле имени управляет видимостью: скрытые объекты не рисуются, не выбираются мышью в сцене и не показывают gizmo; скрытый свет не освещает предпросмотр. Через список Scene или членов группы объект по-прежнему можно выбрать для настройки.

Один объект может входить в несколько групп. Если хотя бы одна из них скрыта, объект скрыт. Это не меняет IsActive, коллайдеры или игровые связи. В игре редакторская видимость игнорируется. Группы, их видимость и принадлежность объектов сохраняются в map; старые уровни открываются без групп. Дублирование копирует принадлежность, Undo удаления восстанавливает её. Создание/удаление групп, изменение состава и видимости поддерживают общую Undo/Redo историю. Группы не имеют Transform.

### Корутины: локальные задержки и анимации

В Object доступны StartCoroutine(IEnumerator), StopCoroutine(Coroutine) и StopAllCoroutines(). Coroutine.Stop() также отменяет конкретное выполнение; IsCompleted и IsCancelled сообщают его состояние. Подключи System.Collections для IEnumerator.

```csharp
private Coroutine? _opening;

public void Open()
{
    StopCoroutine(_opening);
    _opening = StartCoroutine(OpenSequence());
}

private IEnumerator OpenSequence()
{
    yield return new WaitForSeconds(0.3f); // Игровое время.
    var start = Transform.Position;
    var target = start + new System.Numerics.Vector3(0, 2, 0);
    var elapsed = 0f;
    while (elapsed < 1f)
    {
        yield return null;
        elapsed += Application.DeltaTime;
        Transform.Position = System.Numerics.Vector3.Lerp(start, target, Math.Clamp(elapsed, 0f, 1f));
    }
    Transform.Position = target;
    yield return new WaitForSeconds(1f, useUnscaledTime: true);
}
```

Для анимации независимо от TimeScale используй Application.UnscaledDeltaTime вместо DeltaTime. Это изменение трансформа, без автоматической проверки пути или сил. Для перемещения персонажа используй CharacterController.Move, а для BrushBox включи Movable.

StartCoroutine выполняет последовательность сразу до первого ожидания. yield return null продолжает на следующем обновлении мира; WaitForSeconds использует игровой или независимый шаг. Можно возвращать вложенный IEnumerator или Coroutine, чтобы дождаться завершения. Возобновление выполняется после обновления объектов мира, до менеджера таймеров и Physics.Update. Новые корутины, запущенные во время обновления, не продолжаются повторно в том же кадре. Нулевая задержка тоже ждёт следующего обновления. Точность задержек ограничена кадрами.

Корутины принадлежат объекту. Неактивный владелец приостанавливает их, включение продолжает; уничтожение, Stop и выгрузка мира отменяют и освобождают вложенные итераторы с выполнением finally. Сам Start при повторном включении не вызывается. Корутины статичных объектов также обновляются. При TimeScale = 0 ожидание игрового времени стоит, независимого — продолжается; yield return null продолжает каждый кадр, поэтому анимация должна использовать соответствующий deltaTime. В режиме редактора запуск запрещён, Update мира с simulate=false не продолжает корутины. Для обычного World.Update без третьего аргумента оба шага времени равны; базовый Game передаёт их раздельно.

Исключение завершает одну корутину и записывается в журнал; остальные продолжают работу. Корутины не являются потоками: долгий код без yield блокирует кадр. Сохранение текущего выполнения в файл уровня и система твинов не добавлены.
